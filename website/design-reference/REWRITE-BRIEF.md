# oberth.ci — site rebuild (tiny-FAB rewrite)

You are building the production oberth.ci marketing site. The **single source of truth for
look, copy, layout, and behavior is `reference/oberth-site-reference.html`** — an approved,
fully working prototype. Open it in a browser first. Your job is to reproduce it faithfully
as a clean production build, not to redesign it.

## 0. Ground rules

- **Do not change copy, colors, spacing, or animations** without being asked. Every sentence
  in the reference was deliberately worded (and fact-checked against internal architecture
  docs). If something seems wrong, flag it — don't silently "improve" it.
- **No frameworks.** The whole prototype is one HTML file with vanilla JS. Production should
  be the same technology: static HTML + one CSS file + one or two JS files. No React, no
  Tailwind, no build-time CSS framework. A minimal bundler (Vite/esbuild) for
  minify/fingerprint is fine.
- Budget: **≤ 180 KB gzipped total** (html+css+js, excluding fonts), zero layout shift,
  Lighthouse ≥ 95 across the board.
- Fonts: Inter (400–800) + JetBrains Mono (400–700). **Self-host woff2** (EU/privacy
  posture — no Google Fonts request at runtime). Subset latin.
- Accuracy constraints baked into the copy (do not drift): 13 MCP tools (exact names in the
  Agents page table) · no Argo anywhere · SSH NodePort 30022 / HTTPS-MCP 30443, TLS 1.3 ·
  FIFO default 3 concurrent · 30 min/step, 12 h/job · logs ≤ 64 MiB · 5-min uplink issue
  locks · tags creation-only · secrets = literal `ReleaseSecrets` ∩ admin allowlist ·
  Sectigo RFC 3161 + Rekor + immutable K8s records.

## 2. The two-body sim (section 00, home) — the crown jewel

Canvas animation, ~19rem tall. Reproduce **exactly**; all logic is in the reference IIFE
(`oberth effect two-body sim`). Key spec if you refactor:

- Real physics: semi-implicit Euler, 4 substeps/frame, time-scale ×2.6. GM ∝ canvas height.
- Geometry: planet (r=60, Jupiter line-art: warm gradient base, 8 clipped latitude-band
  ellipses, 2 filled zones, Great Red Spot, limb shading, purple ring) at (50%, 30%).
  Vertical-major orbit: **periapsis directly below the planet** (rp = planetR+42),
  apoapsis far above the frame (ra wanted = 1.7·H, clamped so semi-minor b ≤ cx−56).
  Dashed reference ellipse; periapsis tick + 12px label. No apoapsis label.
- Two ships, launched through a **global stagger gate (9.6 sim-s ≈ 3.7 s real; applies to
  every launch and relaunch — two ships must never appear together)**. Spawn at true
  apoapsis with vis-viva velocity, then silently integrate until just above the frame, so
  entries are physically real. Ships: prograde = long dart, warm-white hull, pulsing green
  nav light; retrograde = stub with twin fins, red-tinted hull, red nav light (phase-offset).
- Per-ship mini CI list (10px mono chip; checkout/lint/test/build/package) follows the
  ship, flips sides near the right edge, and **renders only while the ship is inside the
  frame** (this fixed two border-riding bugs — keep the guard). Green ship: steps 1–4
  complete during the coast (progress ∝ radius), **`package` flips ✓ exactly at the
  periapsis burn**. Red ship: `build` is always the doomed step — pending through coast,
  **flips ✗ exactly at periapsis**, later steps stay dim.
- Burns at periapsis (detected via radial min): prograde → Δv to 1.18·v_esc over 0.6 s,
  steady green exhaust, expanding green pulse ring → hyperbola. Retrograde → speed to
  0.45·v_circ, **sputtering** exhaust (70% duty) + yellow/orange misfire sparks, red pulse
  ring → collapsing orbit, sparks trailing all the way down → impact: 46-particle debris,
  fading scorch mark, red "issue #47" text rising & fading.
- Green ship then **rendezvous-docks at the "upstream" hub** (right side): damped guidance,
  then an eased `docking` phase (position lerp + heading lerp — no snapping), trail
  retracts point-by-point, ship parks at the port. Hub: line-art station — rotating
  6-spoke ring, filled core, dock arm with solid berth block + occupancy-blinking port
  lights, cyan-glass solar wings with grids, filled comms dish, red beacon riding the
  ring; label `upstream`, and while docked a green `✓ synced` line + a green payload dot
  repeatedly traveling arm→core. After ~2.4 s the slot recycles (stagger gate applies).
- Backdrop: 190 dust + 80 field + 9 glint-cross stars, all twinkling, plus 4 soft galaxies
  (one edge-on, others with faint spiral arcs).
- Status bar: two live segments (`◆ green-ship msg · ◆ red-ship msg`); exact strings in
  reference. Click canvas = fast-forward. `prefers-reduced-motion`: no animation loop —
  pre-step a static frame **only if the canvas has dimensions**.
- Canvas is DPR-aware (cap 2) and must re-`size()` when its page becomes visible
  (`window.obSimResize` is called on route→home in the prototype).

## 3. System schematic (section 02, home)

HTML/CSS flow diagram, horizontally scrollable below 54rem:
`AI AGENT → (git push) → INGRESS[2 chips] → (one run) → BURN[3 chips] → (green) →
EGRESS[2 chips] → (synced) → UPSTREAM`, with a red drop-line + arrowhead from BURN down to
`✗ Issue queue`, and a **measured dashed-red return connector** from the issue chip back to
AI AGENT (label "agents lock & fix → new push", dot flowing right→left). The return
connector is positioned in JS from live bounding rects (`layoutReturn()`), re-run on
resize, font-load, and route→home — keep that, it cannot be done reliably in pure CSS.
Lane arrows are CSS triangles vertically centered on the line; lane dots animate along;
green lanes tinted. UPSTREAM node's second line is the **small rotor** (github/codeberg/
gitlab, `--rh:1.6em`, phase-offset from the hero rotor). Audit chain = quiet chip in the
schematic header. Chips navigate to their subject page (PAGEMAP above). Below: the 4-
sentence caption ("One push, one Job, one verdict…").

# DRAFT: v0.22.8

## Operators

### Upgrade order

Stop new submissions, take a backup, then upgrade with the v0.22.8 client.
A version-changing upgrade now waits for active Workflows before its built-in
backup or changes. The default deadline is two hours. Use `--wait-for=30m` to
choose another idle deadline; rollout `--timeout` is separate. For example:
<!-- Sources: out/t2-waitidle.REPORT.txt, RELEASE NOTES; int/v0.22.8:docs/releases/drafts/v0.22.8.md. -->

```sh
oberth upgrade --context CONTEXT --namespace oberth --wait-for=30m --argo-security-defaults
```
<!-- Sources: out/t2-waitidle.REPORT.txt; land/v0.22.7:docs/releases/v0.22.7.md, Install, upgrade and restore. -->

The countdown shows active Workflows and time left. Timeout or an unreadable
cluster refuses the upgrade before changes. The selected Kubernetes credentials
need permission to list Workflows in the installed pipeline namespace.
Waiting does not stop admission; keep submissions stopped while draining.
`--no-wait-idle` skips the wait and warns that old runs can fail on their next
step. Same-version reruns, dry-run and rollback do not wait. The upgrade command's
old `--wait-for=all`, `--wait-for=critical` and `--wait-timeout` are removed;
`--wait-for` now takes a duration.
<!-- Sources: out/t2-waitidle.REPORT.txt; ../v0224/OWNER-DECISIONS.md, 2026-11-14 03:40. -->

When upgrading directly from v0.22.6 or older, first make the one-time history
backup with the client matching the running server. Then run the new upgrade
with `--no-backup`, as described for v0.22.7. A kubeconfig alone does not provide
the unscoped admin connection required by the new administration API.
`--argo-security-defaults` consents to filling absent Argo defaults; interactive
review approval is the alternative. Explicit operator settings are preserved.
These checks still apply with `argo.podPolicy.enabled=false`.
<!-- Sources: land/v0.22.7:docs/releases/v0.22.7.md; ../v0224/OWNER-DECISIONS.md, 2026-11-14 02:10, 02:15 and FIXWAVE-v0227-R2. -->

Apply native cleanup defaults before deploying the server. Ordinary upgrade
fills an absent `controller.workflowDefaults.spec.ttlStrategy` with
`secondsAfterCompletion: 3600`. Explicit null, empty, zero and custom values are
preserved and reread before apply. External controllers, skipped Argo
reconciliation and server-only chart deployments must set their cleanup defaults
first. A completed Workflow may otherwise have no TTL.
<!-- Sources: out/t2-logs.REPORT.txt, Workflow cleanup and upgrade ordering; out/t2-int.REPORT.txt, Native cleanup. -->

After deploying, run `oberth secretstore sync` and reconcile the chart's
ServiceAccounts to materialize the exact workflow/step identities. Existing
secret approvals remain; this is not another approval reset. Approval changes
apply at the next admission, but existing OpenBao tokens can retain access until
policy sync or expiry. Missing identities refuse admission. The old
`oberth-secret-access` ConfigMap is ignored and may be deleted.
<!-- Sources: out/t2-grants.REPORT.txt, EXACT OPENBAO AUTHORITY, KEPT and RELEASE NOTES; land/v0.22.7:docs/releases/v0.22.7.md, Before and after deployment. -->

New v4 backups store approvals in the database snapshot. Full and secrets-only
restore restore archived approvals. History-only restore preserves the stopped
target's current approvals, including last-minute revocations. Older archives
need the release that wrote them. Restore across chart generations still needs
`oberth upgrade` first. Unreachable target-ownership code and old chart archives
are removed in this train.

### Runs, history and logs

Shared Workflow and Pod watches replace per-run polling. A cluster observation
outage keeps a run unresolved with a timestamped status-unknown reason. Recovery
confirms Argo's final phase with a live read. Restart recovery processes
Workflows completed during downtime, retaining available logs and retiring
executor identities. The watch slice has live reconnect, restart and
cancellation evidence; assembled-train checks remain required.
<!-- Sources: out/t2-s1-2.REPORT.txt; out/t2-s1-3.REPORT.txt; out/t2-s1-4.REPORT.txt; int/v0.22.8:docs/releases/drafts/v0.22.8.md. -->

Accepted runs submit immediately, independently of the caller's connection.
Create failures show a reason and need an explicit new attempt. Argo controls
parallelism. Promotions are planned immediately; a moved target causes another
prepare/test attempt. Four or more promotions racing for one target can exhaust
two automatic retries and need `promote_retry`.
<!-- Sources: out/t2-queue.REPORT.txt, RELEASE NOTES; T2-INTEGRATION-NOTES.md, t2-queue R2 follow-ups. -->

Container logs stream from Kubernetes and have one bounded stored copy per
container. The default aggregate run limit is 64 MiB. Missing, interrupted or
truncated copies carry reasons. Native helpers are hidden from default log
discovery; explicit scoped reads remain available. Plain live streams are
limited to 32 per server; excess requests return HTTP 429.
<!-- Sources: out/t2-logs.REPORT.txt; out/t2-int.REPORT.txt, Container logs. -->

The client plugin adds `/oberth:runs` and `/oberth:watch`, plus status and pinned
run lines. CLI errors show a sanitized first error line. Watching stops after
three consecutive failures; `/oberth:watch --off` clears the pinned line.
Module tool registration ships disabled; models use `run_list` and `run_get`.
<!-- Sources: out/t2-plugin-tui.REPORT.txt; ../v0224/OWNER-DECISIONS.md, 2026-11-14 03:40 and 03:50. -->

Step/log correctness fixes, database-backed grants and the administration-role
preflight remain pending. Default upgrade waiting and the hook/cancellation
follow-ups are integrated. These draft notes do not establish release readiness.

## Repository authors

Authored `ttlStrategy` and `podGC` pass through unchanged. Leave enough time to
observe completion and capture logs. Aggressive PodGC can remove logs before
capture; a Workflow deleted before completion is observed can also lose its
verdict. Step rows and log selection use Argo node IDs across retries, nested
DAGs, ContainerSets and exit handlers. Marker-looking log lines stay ordinary
text. The latest integration report's step/log fixes are still pending.
<!-- Sources: out/t2-logs.REPORT.txt; out/t2-steps.REPORT.txt; out/t2-int.REPORT.txt. -->
<!-- PENDING: t2-steps -->

Overlapping schedule occurrences get independent Workflows. Cron coalescing and
the manual busy guard are removed. `force` only overrides a paused entry.
Native CronWorkflow activation belongs to v0.23.1.
<!-- Sources: out/t2-queue.REPORT.txt, Scheduled runs; ../v0224/OWNER-DECISIONS.md, 2026-11-14 02:20 and 03:00. -->

Hooks invoking secret-store or cloud-identity leaves refuse keys containing
`.`, `(`, `)`, `[` or `]`. Ordinary-leaf hooks keep those names. Rename affected
hook keys before the next run. Unreferenced empty hook keys are allowed;
referenced credentialed shared-container results remain refused. Refusals identify
the hook and invoking step or task, including inline parents. The retired saved
release-status dashboard filter fallback is removed.

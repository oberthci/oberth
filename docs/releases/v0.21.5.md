# v0.21.5

## #1524 — Agent flow review

- Admin-only `tag_after` refuses release-version names, including prereleases.
- Automatic retries preserve assist, wait five seconds before dispatch, and use the current audit receipt format only.
- CI compares migrations with the fetched default branch, including before the sequence file first exists there.
- Resource exports anonymize refs named `any` and `default` too.

## #1527 — Scripted install and verification

- Strict versioned YAML/JSON answers cover the wizard and can be exported at Review.
- Installation requires `--yes`; a local public key can create the first admin before forge onboarding finishes.
- JSON verification reports endpoints, the DER CA pin, identity, and checks with remedies.
- Once-only credentials are saved immediately, with optional age encryption and upstream key recovery copies; save failures fail the install.

## #1528 — Cluster plan and preflight

- Plan JSON reports the selected kubeconfig files, context, API identity and node facts with actionable preflight checks.
- Multi-file KUBECONFIG preserves the requested context across API, Helm and kubectl calls.
- Fresh k3s requires an operator-owned private kubeconfig copy; root configuration and macOS kind are no longer selected implicitly.
- Verify JSON includes node readiness, free disk, architecture, storage and network-policy checks. Every cluster uses the same Review confirmation.

## #1529 — Verified plugin bootstrap

- Releases publish checksums for all four CLI binaries and the chart, plus a raw DER ECDSA P-256 signature that OpenSSL can verify with the pinned release public key.
- Publication checks the checksum signature against the authenticated Sigstore bundle and checks every digest against the signed release record.
- The plugin fetches a requested or newest version with curl or wget, OpenSSL, and sha256sum or shasum. Verification failures preserve the existing install.
- `/oberth:install` uses the plugin fetcher. Command tool permissions name only the plugin's own scripts, and CI checks the plugin, release pipeline, and compiled-in CLI key pins together.

# Oberth v0.17.82 priority changes

- Submission priority only raises a run's automatic class. Promotions and eligible
  oldest tags retain `highest`, RC patterns retain `high`, and refused/invalid
  requests appear separately in `priority_refusal`. Priority requester ownership
  never grants admin cancellation rights for tag, release, promotion or
  concurrency-group work.
- Queue order uses effective class, then base class, then original FIFO order.
  Explicit `highest` precedes aged normal work when capacity frees. Aging alone
  cannot guarantee a time bound under a continuous stream of base-highest work.
- Protected priority and RC runs survive ordinary supersession. Every matching
  RC push queues and runs independently. `oberth.supersede=true` is honoured on
  priority pushes, but replacing protected work requires its requester or an
  unscoped admin; branch, schedule-entry, promotion and publication guards apply.
- `schedule_trigger force` bypasses busy/paused checks and replaces only
  unprotected same-branch, same-entry work for a normal-priority submission.
  Protected work remains; priority schedule submissions queue independently.
- For this release, every backfill behind a high/highest head is refused. Normal
  heads keep bounded backfill. The EASY reservation rule will replace this
  conservative guard in a subsequent integration.
- Trusted preflight recovery and eligible automatic infrastructure retry retain
  protected work's own admission place alongside newer normal pushes. Recovery
  cannot supersede those siblings, and existing retry/evidence guards remain.

See [release priority and fairness](../release-priority.md) for queue semantics
and administrator controls.

## #1537 — API and installer review corrections

- Migrate stored priority names to the four current classes and remove the aliases.
- Re-check moved promotion targets for ancestry before `tag_after` retries, preserve the request through promotion retries, and persist intent before tag pushes.
- Bound run-list globs with an indexed literal prefix; verify scoped latest results, route-wide metrics refusal and the configured SSH host key in system status.
- Preserve an adopted retry attempt's script output when the previous attempt has a durable log cursor.
- Cancel installation on SIGHUP, resume production configuration from a private recovery file (including age-encrypted input), and update existing SSH ports.
- Keep identical upstream registrations after deploy-key regeneration; restore prints the installation's public deploy key and forge registration/check instructions.

- SSH setup recognizes tab-separated, equals-separated and quoted Host headers, and restored upstream registration conflicts are refused before identity changes.

## #1537 item 9(c) — Tag-after CI admission

- A verified `tag_after` publication now queues ordinary tag CI through the
  shared receive/admission path. Durable receive IDs prevent another run after
  an admission/settlement retry or restart; the reason names the queued run.
- Non-version tags use `build.yaml` with tag identity and CI authority. Release
  versions and explicit administrator release routes retain release admission;
  `tag_after` refuses both. Normal tag CI never acquires release authority from
  its tag trigger, including on adoption and rerun.
- Tag objects and tested commits stay separate. Existing default-branch ancestry,
  immutability, audit and publication gates continue to apply.

## #1532: Repository onboarding from the plugin

`/oberth:add-repo [path]` detects the forge and organization, uses Oberth's
existing upstream configuration and verification, and adds a repository deploy
key through authenticated gh/glab/tea only with consent. Without a usable CLI,
it gives the exact repository settings URL and waits for a manual key paste.

The flow offers an `oberth` remote or origin push URL, sets assist only in the
repository's Git config, previews an optional native language workflow, and
waits for a matching smoke run through the agent loop. It never stages or
commits user files; workflow commits and the smoke push require approval.

- Deploy-key uploads accept one public key and strip comments; smoke pushes bind the approved commit and one destination, refusing changed HEADs or additional push URLs.

# v0.21.10

## Scheduling and host preparation (#1542)

- Admission now packs whole Workflows by effective concurrent CPU requests,
  reserving 20% of allocatable CPU for platform and host work. Exit handlers and hooks are bounded; truly unknown graphs reserve the pool and
  oversized fan-out is
  clamped, so valid workflows continue to submission. Restart demand-read errors
  degrade to live Pod accounting, conservatively reserving the pool on read failure.
- After five complete successful runs, main-container requests use P95 of
  lifetime-average CPU plus 25%, floored at 10% of the declaration and 50m, instead of instantaneous peaks.
  The decision is frozen before admission and retained for retries.
  Step container CPU requests are capped at 25% of node allocatable CPU;
  limits stay available for bursts. On a 12-CPU node, the pool is 9600m and
  each container requests at most 3000m, plus the executor allowance.
- Promotion and release priority reaches Argo `spec.priority: 1`; high is 2,
  standard is 0 and low is -1. Equal-priority repositories share admission
  by active-run count and last service before FIFO. A capacity-blocked pool allows two minutes of backfill, then protects its
  oldest head until it starts. Assistance retains all resident and sibling
  Pod requests, including through continuation.
- Default CPU pressure threshold is now 25% some PSI avg10. A fitting run's
  PSI deferral is bounded at 300 seconds, with at most one hard-pressure bypass
  per window. CPU budget and administrative holds
  still apply. Ordinary CPU-capacity waits remain exempt from startup expiry;
  only Pods larger than the largest eligible node expire after 10 minutes.
- Managed OpenBao and Argo controllers retain the shared control-plane
  PriorityClass and now request 100m CPU and 128Mi memory. Apply the same
  protection to custom ingress or tunnel deployments.
- Install plans warn about absent or unverified swap/zram, low inotify limits,
  and missing kubelet system reservations or memory eviction, with exact remedies.

See [CPU defaults and overrides](../cpu-admission.md),
[host preparation](../host-preparation.md), and
[dependency protection](../platform-protection.md). The node snapshot uses the
sum of Ready schedulable untainted nodes for capacity and the largest for step
caps. Remote targets use their own cluster; `admission.cpuEnabled: false` disables
CPU admission and request resizing. Capacity refreshes every minute; unavailable
capacity holds only its pool while the server keeps serving. Argo's existing parallelism remains an additional cap.

Resource-only submissions include executor CPU/memory in valid recovery bindings.
Malformed optional demand metadata falls back to live observation without
blocking unrelated adoption. Static fan-out without workflow parallelism is
limited to what the pool fits. Full lookahead still admits urgent claims.
The fair-share indexes build during startup migration; very large databases
need measured maintenance, free-space and startup-probe headroom. See the
[upgrade migration notes](../cpu-admission.md#upgrade-migration).

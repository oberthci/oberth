# v0.21.10

## Scheduling and host preparation (#1542)

- Admission now packs whole Workflows by effective concurrent CPU requests,
  reserving 20% of allocatable CPU for platform and host work. Unknown graphs reserve the whole pool and oversized fan-out is
  clamped, so valid workflows continue to submission. Restart demand-read errors
  degrade to unknown with a bounded credit lease.
- After five complete successful runs, main-container requests use P95 of
  lifetime-average CPU plus 25% (50m floor), instead of instantaneous peaks.
  The decision is frozen before admission and retained for retries.
  Step container CPU requests are capped at 25% of node allocatable CPU;
  limits stay available for bursts. On a 12-CPU node, the pool is 9600m and
  each container requests at most 3000m, plus the executor allowance.
- Promotion and release priority reaches Argo `spec.priority: 1`; high is 2,
  standard is 0 and low is -1. Equal-priority repositories share admission
  by active-run count and last service before FIFO. Aged capacity holds alternate
  drain and backfill windows; long assisted holds release admission credits.
- Default CPU pressure threshold is now 25% some PSI avg10. A fitting run's
  PSI deferral is bounded at 300 seconds. CPU budget and administrative holds
  still apply. Insufficient-CPU Pod waits expire after the existing 10-minute
  admission timeout, including later steps and after observer restarts.
- Managed OpenBao and Argo controllers retain the shared control-plane
  PriorityClass and now request 100m CPU and 128Mi memory. Apply the same
  protection to custom ingress or tunnel deployments.
- Install plans warn about absent or unverified swap/zram, low inotify limits,
  and missing kubelet system reservations or memory eviction, with exact remedies.

See [CPU defaults and overrides](../cpu-admission.md),
[host preparation](../host-preparation.md), and
[dependency protection](../platform-protection.md). The node snapshot uses the
sum of Ready schedulable untainted nodes for capacity and the largest for step
caps. Remote targets use their own cluster; `admission.cpuEnabled: false` disables
CPU admission and request resizing; restart Oberth after
capacity changes. Argo's existing parallelism remains an additional cap.

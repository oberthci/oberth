# v0.17.81 candidate integration

This candidate integrates token lifetime enforcement, SSH cache recovery,
issue metadata revision checks, publication abandonment, API compatibility
aliases and retired-code cleanup.

Migrations run together from v38: v39 adds nullable bearer expiry; v40 adds
issue metadata revisions; v41 rebuilds publications with the terminal
`abandoned` verdict. Existing credentials keep a NULL expiry. New credentials
default to 90 days and are capped at 365 days by server policy.

Restore a verified v38 database backup before running this candidate on any
database previously opened by the discarded experimental issue-workspace
build, whose migration 39 has a different meaning. Restore is also required
for rollback; Helm rollback alone cannot undo these migrations.

`GET /api/issues` and `oberth issues --json` return summaries without `Body`,
`ScopeUpstreamID` or `CIWorkSequence`. Read issue detail for body text. This is
an explicit v0.17.x privacy exception to additive compatibility. See
[API compatibility](../api-compatibility.md).

The public Go import path `pkg/periapsis` is replaced by `pkg/pipeline`.
Downstream Go imports must change. Wire names such as `Burn` and `FailedBurn`
remain stable. Failure attribution chooses the first failed step in declared
order; subsequent cleanup failures remain available as step evidence.

Publication abandonment is audited, never pushes Git objects, and terminates
its owner. The failed owner is projected into the ordinary CI issue history.
Abandoned publications are terminal and cannot be retried.

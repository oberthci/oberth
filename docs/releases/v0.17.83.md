# Oberth v0.17.83 candidate

This small release builds on [v0.17.82](v0.17.82.md). It contains run-list
ordering, queue aging and the shared run-status vocabulary. The former larger
candidate is combined into [v0.17.84](v0.17.84.md).

## Run order and aging

Lists show queued work first, then running work by newest start, then finished
work by newest finish. Within the queue, the next admitted run is at the
bottom, closest to running work. Paging limits only finished rows; queued and
running rows remain on the first page. Normal runs age into high after 60
minutes, keeping their queue position; aging never grants highest. Sustained
highest-priority arrivals can still delay high and aged work.

## Status vocabulary

Runs use `queued`, `running`, `passed`, `failed`, `infra-retried`, `superseded`
or `cancelled`. Claimed work before admission shares one grey queued pill
with a reason line. Admitted work, including trusted preflight, is running.
Clients using `waiting`, `infra-pending` or `deadline-exceeded` display values
must read the consolidated status and reason. Raw machine fields remain.

## Upgrade from v0.17.82

Keep a verified database backup and its matching private key. The small-release
branch assigns migration 40 to the run-list covering index, advancing schema
39 to 40. This conflicts with migration 40 in the combined v0.17.84 candidate;
that candidate refuses this lineage. A reviewed reconciliation is required
before upgrading from this small release to v0.17.84. Do not rewrite the
ledger or bypass schema checks. CI and live upgrade qualification remain
required.

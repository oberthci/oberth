# Oberth v0.17.83 candidate

This candidate builds on the [v0.17.82 candidate](v0.17.82.md). Its database
migrations continue in order from 39 through 48. Chart version 0.17.83 and
application version v0.17.83 identify this candidate; independent CI and live
release qualification remain required.

## Authentication, issues and publication

Failed authentication responses retain a ten-failure credential bucket and
add an independent 100-failure transport-peer ceiling per minute. Forwarded
headers cannot change the peer key. Valid credentials behind shared ingress
continue to work. This shapes failure responses and does not bound backend
credential lookups. The dashboard prompts on HTTP 429 and explains retrying.
Authentication log fields now use quoted values, for example
`reason="invalid_token"`; log searches must account for the quotes.

Issue updates use metadata revisions. Publication abandonment remains
successful when local pin cleanup fails, reports the cleanup warning and
retries abandoned pins during repository refresh. Pending publication pins
remain protected. Restart recovery retains timing history and tag publication
identity, preserves protected same-ID recovery beside newer siblings, and
finishes prior Workflow cancellation before same-ID execution resumes.

## Workflow policy and execution

Workflow deadlines default to 30 minutes when omitted, bounded by repository
and server policy. Shorter declared values remain effective. Trusted
preflight deadlines begin at admission. The API and dashboard show preflight
and Workflow execution clocks separately. Local `oberth validate` retains
stricter validation of omitted deadlines.

The server watchdog uses Workflow start time, or creation time before startup,
and adds the greater of two minutes or ten percent as grace. This lets Argo
record its deadline failure before server cleanup. Completed Workflows stop
the watchdog before diagnostic collection. Terminal preflight cleanup retries
without a restart: admission releases promptly, while VM capacity remains
reserved until exact-run absence is confirmed.

Seeded runs now declare the run PVC once per Pod. Source and artifact subPaths
share that volume, while source, CA and binary mounts remain read-only and
artifact writes follow workspace policy. This avoids the local-PV mount stall
caused by two aliases for the same claim. Existing persisted Workflows are not
rewritten by this renderer correction.

Runtime retirements and explicit repository Workflow capabilities are
documented in [the retirement guide](unreleased-execution-retirement.md) and
[Workflow capabilities](../workflow-capabilities.md). Numeric CPU and memory
ceilings replace size-grant authority; existing grants migrate without
granting new capability authority. See [declared resources](../declared-resources.md)
for requests, limits and legacy admission behavior. The release leaves retain
4 CPU / 8Gi ceilings, bounded Go workers and a 4GiB release-test Go soft target.

## Upgrade and qualification

Back up the database and confirm its migration lineage before upgrading.
The sequence is token expiry 40, issue revision 41, publication abandonment
42, restart timing 43, tag publication identity 44, pilot retirement 45,
Workflow capabilities 46, deferred execution retirement 47 and resource
ceilings 48. No placeholders or renumbered production migrations are used.
Helm rollback does not undo these database changes.

Follow the documented capability, namespace audit and retired connector
ownership prerequisites before rollout. Local SQLite, fake-client controller
proofs and test suites cannot qualify live WIF/IAM, network policies, PKI,
cleanup finalizers, publication or database lineage. Cold release duration
and Pod memory headroom at the declared ceilings remain live CI measurements.

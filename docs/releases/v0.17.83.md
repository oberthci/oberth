# Oberth v0.17.83

The run list groups queued runs, running runs by newest start, and finished
runs by newest finish. Every queued group follows scheduler claim order:
highest effective priority first, including aged high work, then FIFO. The
first page includes all active work; only finished runs count toward the page
limit. This applies to the dashboard, HTTP, MCP
and CLI, including latest-per-ref lists.

Normal runs waiting at least 60 minutes age into high at their original queue
position. Aging never raises high work into highest; explicit highest work
still leads. Sustained highest arrivals can delay high work without limit.

Schema migration 40 widens the latest-per-ref index for grouped paging. Keep a
verified database backup before upgrading. Rolling back requires restoring
the matching backup; older binaries refuse the newer schema.

Durable queued runs and claimed runs awaiting admission share one grey
`queued` status, with a reason line for position, capacity or preparation.
Admission records the start: admitted work, including trusted preflight,
shows `running`. Claimed and unclaimed work share one effective-priority queue.
The former `waiting`, `infra-pending` and `deadline-exceeded` display labels
are replaced by existing `queued`, `running` or `failed` values with a reason.
Raw status and scheduling fields remain available for machine clients.

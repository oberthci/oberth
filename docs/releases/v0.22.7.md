# v0.22.7

## Operators

### One-time backup before upgrading from v0.22.6 or older

Before the administration API cutover, use the verified CLI matching the
running server to take a history backup. Keep the encrypted archive and its
decryption key. Then use the new CLI with `oberth upgrade --no-backup`, selecting
the same Kubernetes context and namespace. For a v0.22.6 server:

```sh
./oberth-v0.22.6 backup --history-only --context CONTEXT --namespace oberth
oberth upgrade --no-backup --context CONTEXT --namespace oberth --wait-idle
```

Stop new submissions while waiting. `--wait-idle` is advisory; it does not freeze
admission. If Kubernetes observation is unavailable, confirm there are no active
Workflows before intentionally omitting wait flags. `--no-backup` does not attach
the manually saved archive to the automatic rollback record. Preserve it for
manual recovery. History backups do not contain OpenBao secret values or
server-volume logs and artifacts.

Integration prerequisite: this procedure is required by the reviewed S8 slice
and the upgrade decision. That slice is absent from the documentation base;
the base still uses exec for database backups. Do not treat the administration
API cutover or its new refusal message as verified on this base.

### Install, upgrade and restore

Kubernetes 1.33 or newer remains required. The managed Argo chart is 1.0.24,
qualified with Argo v4.0.8 and a pinned executor image. Keep both the task-result
and executor-holder admission policies and their Deny bindings installed. Review changed controller
configuration and resulting Pods before using a different controller build.

Install and upgrade inspect effective live Argo main/executor security defaults,
including Pod and template defaults. On an existing Argo release, approve the
review or pass `--argo-security-defaults` to fill absent settings. Explicit
operator settings are preserved; incompatible settings require correction.
External ConfigMaps must be configured at the live controller. These checks
still apply when `argo.podPolicy.enabled=false`.

The Pod policy requires no privilege escalation, drop ALL capabilities, and
effective RuntimeDefault or Localhost seccomp on step containers. It allows
root, writable root filesystems and adding only NET_BIND_SERVICE. Pod-level
Unconfined is refused even if containers override it. The pipeline namespace
still needs privileged Pod Security labels for the existing cache hostPaths;
baseline labels belong to the v0.23.0 draft.

Drain active Workflows before changing executor identities. The reviewed
executor follow-up reports that old in-flight steps can fail their next
task-result write and need another attempt. Its further DELETE protection and
one-second start margin are integration prerequisites absent from this base;
the margin reduces a shared-template startup race and does not close it.

Execution targets and the Go module proxy are removed. Upgrade retires their
stored installer settings; remove obsolete overrides from operator files and
scripts. Reinstall and restore encountering removed Go proxy settings instruct
operators to run `oberth upgrade` first. Do not use restore as a substitute for
the chart upgrade. If upgrading from before v0.22.5, **all secret approvals are
cleared; re-approve**. That clearing belongs to v0.22.5, not a second v0.22.7
reset.

After upgrading, apply consuming repositories' run-fact YAML changes before the
next release run, check effective controller defaults, and exercise one ordinary
run and its cancellation. Read-only install planning remains read-only; live
NetworkPolicy measurement happens during install after approval. Full train CI
and live qualification remain release gates.

## Repository authors

Run facts now arrive as native Workflow parameters, including `oberth-repo`,
`oberth-ref`, `oberth-sha` and `oberth-trigger`. Map them into container env
explicitly. Use `{{workflow.name}}` for the run ID. Release-only parameters are
`oberth-release-tag` and `oberth-release-sha`. The `oberth-` parameter/globalName
prefix is reserved. Refs must begin with a letter or digit and contain only
letters, digits and `. _ / + @ = , -`; rename unsupported refs before running.

Fragments are removed. Inline shared YAML for this release. All `templateRef`
and `workflowTemplateRef` forms remain refused on this base. Namespaced native
template sharing is a v0.23.0 draft, with no reviewed implementation here.

Reported SEC-A integration prerequisite: authored security contexts pass through
unchanged, the nonroot annotation and injected `/tmp` disappear, and authors
declare their own scratch and helper contexts. Credentialed steps need absolute
output parameter paths outside mounts; steps with sidecars or multiple
containerSet members cannot use path-read outputs or referenced results. These
changes are verified only in the separate slice, not this base. Every container
of such a step shares its trust; output guards do not isolate containers.
That slice also retires the unused `argo.executorScratchSizeLimit` setting and
its CLI flag; its install/upgrade/restore cleanup preserves unrelated values.

Admission now leaves native sizes, fan-out, names and deadlines to Argo and
Kubernetes. Tag-only images, `imagePullSecrets` and `resourceFieldRef` are
admitted. The built-in image list is gone; an optional operator allowlist
remains. Security and ownership refusals remain, including memoization. New
Workflow metadata checks reserve Argo controller keys; the supported
`workflows.argoproj.io/pod-name-format` annotation is an exception.

Ordinary branch cancellation requests Argo Stop and allows exit handlers. Cancel
again while active to request Terminate. Release/tag/apply and promotion
cancellation uses Terminate immediately. Oberth does not delete Workflows;
Argo TTL owns cleanup. Argo Succeeded is passed even with tolerated failed
steps, subject to explicit cancellation and publication guards. Older green
runs cannot publish over a newer accepted branch head. A cancel racing native
success can leave a passed, unpublished run that cannot be rerun.

Secret grants already require the step, exact workflow file and upstream
repository. This release does not yet remove injected secret clients or source
claims. The optional helper image is recorded in signed release metadata.

See the [migration guide](../migrating-to-native-workflows.md) for before/after
YAML, exact refusal messages, fixes and the status of each integration item.

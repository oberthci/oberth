# v0.22.7

## Operators

### One-time backup before upgrading from v0.22.6 or older

<!-- PENDING MERGE -->

Before the administration API cutover, use the verified CLI matching the
running server to take a history backup. Keep the encrypted archive and its
decryption key. Then use the new CLI with `oberth upgrade --no-backup`, selecting
the same Kubernetes context and namespace. For a v0.22.6 server:

```sh
./oberth-v0.22.6 backup --history-only --context CONTEXT --namespace oberth
oberth upgrade --no-backup --context CONTEXT --namespace oberth --wait-idle --argo-security-defaults
```

Use the actual running version when choosing the saved CLI. The new CLI refuses
its built-in backup against an older server before changing anything and prints
the exact commands for the selected version, context and namespace.
`--argo-security-defaults` grants consent to fill absent Argo defaults; interactive
review approval is the alternative.

**v0.22.7 does not drain by default: pass `--wait-idle`** (or `--wait-for=all`).
Stop new submissions while waiting; the wait is advisory and does not freeze
admission. The API cutover observes native Workflows through Kubernetes even
against older servers; a critical wait conservatively includes all active
Workflows. If observation is unavailable, independently confirm that no runs
are active before intentionally omitting wait flags. From v0.22.8,
version-changing upgrades will wait for idle by default; see the
[v0.22.8 draft](drafts/v0.22.8.md).

`--no-backup` does not attach the manually saved archive to the automatic rollback
record. Preserve it for manual recovery. History backups do not contain OpenBao
secret values or server-volume logs and artifacts. Administration operations move
to authenticated APIs. Interrupted first-admin enrollment resumes with the saved
local enrollment identity; first-admin creation retains one guarded install-time
exec. This block awaits the administration API and install-resume merge.

### Install, upgrade and restore

Kubernetes 1.33 or newer remains required. The managed Argo chart is 1.0.24,
qualified with Argo v4.0.8 and a pinned executor image. Keep both the task-result
and executor-holder admission policies and their Deny bindings installed.
Runtime does not check their continued presence. Review changed controller
configuration and resulting Pods before using a different controller build.

Install and upgrade inspect effective live Argo main/executor security defaults,
including Pod and template defaults. On an existing Argo release, approve the
review or pass `--argo-security-defaults` to fill absent settings. Explicit
operator settings are preserved; incompatible settings require correction.
External ConfigMaps must be configured at the live controller. These checks
still apply when `argo.podPolicy.enabled=false`.

The Pod policy requires no privilege escalation, drop ALL capabilities, and
effective RuntimeDefault or Localhost seccomp on step containers. It allows
root, writable root filesystems and adding only NET_BIND_SERVICE. Pod-level
Unconfined is refused even if containers override it. The pipeline namespace
still needs privileged Pod Security labels for the existing cache hostPaths;
baseline labels belong to the v0.23.0 draft.

### Executor identity cutover and step startup

<!-- PENDING MERGE -->

Drain active Workflows, including exit handlers, before changing executor
identities. Without the explicit idle wait, old in-flight steps fail closed on
their next task-result write and affected runs need another attempt. Completion
retires all executor identity holders owned by the Workflow, including old names
and capability accounts. Task-result DELETE is bound to the stored result's
Workflow even if an operator grants delete RBAC. Both policies and their Deny
bindings must remain installed. Use normal cascading Workflow deletion or Argo
TTL; orphan deletion can hang when the holder policy refuses an owner update.

Argo's wait container requires the native Kubernetes
`lifecycle.postStart.sleep.seconds: 1` action. Each step Pod's main container and
sidecars start about one second later, adding about one second per step. The
reported live proof uses Kubernetes 1.33.1. The margin narrows the shared-template
startup race; it does not close it or isolate containers within a credentialed
step. This block awaits the token-hardening merge.

### Before and after deployment

Execution targets and the Go module proxy are removed. Upgrade retires their
stored installer settings; remove obsolete overrides from operator files and
scripts. **Restore across chart generations requires `oberth upgrade` first.**
Reinstall and restore encountering removed Go proxy settings also instruct
operators to upgrade first. If upgrading from before v0.22.5, **all secret
approvals are cleared; re-approve**. That clearing belongs to v0.22.5, not a
second v0.22.7 reset.

Before upgrading, record the count of interrupted runs with an outstanding
cancellation that the native Stop migration will resume observing. Run this
read-only query against a pre-upgrade database copy; it makes no changes:

```sql
SELECT COUNT(*) AS interrupted_with_pending_cancellation
FROM runs AS r
JOIN run_cancellations AS c ON c.run_id = r.id
WHERE r.status = 'interrupted'
  AND c.completed_at IS NULL
  AND c.job_name != ''
  AND c.reason != 'owner_restart'
  AND (r.trigger != 'promotion' OR NOT EXISTS (
    SELECT 1 FROM promotions AS p
    WHERE p.run_id = r.id AND p.status != 'pending'
  ));
```

After deploying the new server, update consuming repositories whose pipelines
used `oberth.ci/nonroot-templates`: remove the annotation, author the desired
security contexts and scratch volumes, and validate with the new CLI before the
next run. Apply run-fact mappings too. When workflow files change, re-approve
their exact grants. A shared pipeline repository must update its own affected
pipelines after deployment as well. Exercise an ordinary run, a granted run and
cancellation, and check effective controller defaults. Read-only install planning
remains read-only; live NetworkPolicy measurement happens during install after
approval. Full train CI and live qualification remain release gates.

## Repository authors

Run facts now arrive as native Workflow parameters, including `oberth-repo`,
`oberth-ref`, `oberth-sha` and `oberth-trigger`. Map them into container env
explicitly. Use `{{workflow.name}}` for the run ID. Release-only parameters are
`oberth-release-tag` and `oberth-release-sha`. The `oberth-` parameter/globalName
prefix is reserved. Refs must begin with a letter or digit and contain only
letters, digits and `. _ / + @ = , -`; rename unsupported refs before running.

Fragments are removed. Inline shared YAML for this release. All `templateRef`
and `workflowTemplateRef` forms remain refused. Namespaced native template
sharing is a v0.23.0 draft, with no reviewed implementation here.

### Authored security settings and credential-output refusals

Authored security contexts pass through unchanged. The nonroot annotation and
injected `/tmp` are removed: authors declare users, groups, scratch and helper
contexts. Argo defaults and Kubernetes enforce the security floor. The unused
`argo.executorScratchSizeLimit` setting and its CLI flag are retired;
install/upgrade/restore cleanup preserves unrelated settings.

The following new refusals apply to steps receiving secret-store or
cloud-identity mounts. Messages use example template `publish` and output
`digest`; substitute your actual names and path. Effective outputs are merged
by name with `templateDefaults` before checking.

| Newly refused shape | Exact example message | Fix |
| --- | --- | --- |
| Any relative output parameter file, even with workingDir on the step's own filesystem | `argojob: credentialed template "publish" output "digest" read path "result" is relative; use an absolute path on the step's own filesystem` | Use an absolute path on the container filesystem outside all mounts. `./result`, `../result` and a path beginning with `{{inputs.parameters.p}}` get this message too. |
| A path on or under any volume mount or input-artifact path, or an absolute path containing a substitution | `argojob: credentialed template "publish" output read path "/work/artifacts/result" is on a volume mount or cannot be resolved before execution` | Write to a literal absolute non-mounted path. This includes credential, CA, scratch and read-only mounts. |
| An inherited relative or mounted output from `templateDefaults` | The corresponding relative-path or mounted-path message above | Override that same output name with a safe absolute path on every credentialed leaf, or remove the default file read. Setting only `value` or `default` does not clear an inherited `valueFrom.path`. |
| File-read output on a credentialed step with sidecars or several containerSet members | `argojob: credentialed template "publish" cannot use path-read output parameter "digest" because another container of the Pod can redirect what Argo reads` | Move output production to a step without other containers, or remove the file read. Relative paths can hit the earlier relative-path refusal first. |
| Referenced stdout result on such a step | `argojob: credentialed template "publish" cannot use referenced outputs.result because another container of the Pod can redirect what Argo reads` | Remove the result reference or use a separate step without other containers. |
| Result-like suffixes such as `steps.publish.outputs.resultSuffix`; references in any invoking-parent field, including labels, workflow Pod metadata or inherited defaults; substituted step/task template names in a result-referencing parent | The referenced-result message above | Remove the capture-triggering text or use literal invocations and a separate output-producing step. These shapes enable Argo's loose stdout-capture matcher even without an ordinary exact result expression. |
| A read-only credentialed root filesystem whose only writable paths are mounted scratch | The corresponding mounted-path message above | Use a single-container step's `outputs.result`, or a writable non-mounted path. With sidecars, move output production or remove the read. |

Sidecars remain allowed without those output reads. Init-only helpers do not
alone trigger the shared-container output rule. Multiple containerSet members
are covered by that rule, but credential delivery currently accepts
Container/Script leaves; it does not enable credentialed containerSet templates.
Every container of a credentialed step shares its trust. These guards do not
isolate containers; Argo retains its native credential and helper mirrors.

Admission leaves native sizes, fan-out, names and deadlines to Argo and
Kubernetes. Tag-only images, `imagePullSecrets` and `resourceFieldRef` are
admitted. The built-in image list is gone; an optional operator allowlist
remains. Security and ownership refusals remain, including memoization. New
Workflow metadata checks reserve Argo controller keys; the supported
`workflows.argoproj.io/pod-name-format` annotation is an exception.

### Cancellation and publication

Ordinary branch cancellation requests Argo Stop and allows exit handlers. Cancel
again while active to request Terminate. Release/tag/apply and promotion
cancellation uses Terminate immediately. Oberth does not delete Workflows;
Argo TTL owns cleanup. Argo Succeeded is passed even with tolerated failed
steps. Publication separately checks cancellation and the accepted branch head:
older green runs cannot publish over a newer head. A cancel after native success
leaves the run passed but unpublished; that passed run cannot be rerun.

Secret grants already require the step, exact workflow file and upstream
repository. This release does not yet remove injected secret clients or source
claims. The optional helper image is recorded in signed release metadata.

See the [migration guide](../migrating-to-native-workflows.md) for before/after
YAML and exact refusal remedies.

# v0.21.1 release candidate

This candidate builds on v0.21.0 and finishes the full code review's human and
agent ergonomics findings. Everything is generic; no run status, label or
layout is added, and no migration.

**MCP tools: 92 → 93.** `events_wait` is new. Non-admin tokens see 46 fewer
tools in `tools/list`; the server still refuses those tools for them.

## Breaking

- `oberth runs --json` prints an object, `{"runs":[...],"next_before":N}`
  (`next_cursor` for scoped uplinks), instead of an array. `--active --json`
  is unchanged.
- `oberth issues` prints one page (at most 50, `--limit`) with a `--before`
  hint; `--all` reads every page as before.

## Connecting

- Every remote CLI command accepts `--url`, `--token-file` and `--ca-file`, and
  with nothing set reads the files `oberth install` writes in
  `~/.config/oberth` (`env`, `mcp.json`, `ca.crt`, `token`). Flags beat
  environment variables, which beat files.
- The saved credentials in `~/.config/oberth` are sent only to the server
  those files name, on every path: the CLI, `oberth client setup` and the
  Claude Code plugin. A different `--url` or variable needs its own
  `--token-file`, `OBERTH_TOKEN` or `OBERTH_TOKEN_COMMAND`.
- Client files that someone else owns or can write (the directory, `env`,
  `mcp.json`, `token`) are ignored with an error naming the file.

## Agents

- New MCP tool `events_wait`: one blocking call (at most 600 s) wakes on the
  next event after a cursor that matches the caller's scope and optional
  filters (`repos`, `refs_glob`, `kinds`, `own`, `run_ids`).
- New CLI commands: `oberth run wait <id>`, `oberth events [--since] [--wait]`
  and `oberth sync status`, with human output and `--json`.
- `run_list` gains `own:true` (runs pushed by the caller) and `held:true`
  (runs with an active assisted hold).
- Blocking tools document `timeout_s` and accept `timeout` and
  `timeout_seconds` as aliases; two different values are refused.
- Hold actions no longer use `assist.maxConcurrentHolds` slots; they stay
  limited to one at a time per run and 64 in flight per installation.
- The repository is a Claude Code plugin marketplace: the `oberth` plugin
  carries the MCP entry (URL from `OBERTH_MCP_URL`, token through a
  `headersHelper`) and the `oberth-agent-loop` skill (#1521). On the server
  host, set `OBERTH_MCP_URL` to the address the client files name.

## People

- A push whose run creation fails after the refs are accepted says so, names
  the kept record, and gives the `oberth outbox show|retry` repair; later
  pushes blocked by it are told nothing was applied. `oberth outbox
  abandon/retry --id` accepts the `<record>:<index>` form the push prints.
- `git push -o oberth.priority_reason=...` is read; unknown `oberth.*` push
  options print a notice instead of being ignored.
- Held runs, `oberth status`, `oberth admission` and the dashboard show the
  administrator hold's whole reason, actor and expiry.
- In-pod commands run from a workstation say where to run them instead of
  printing a SQLite error.
- `oberth run show` and similar verbs are refused with the accepted forms;
  `run`, `runs` and `issues` help list their subcommands; usage errors are no
  longer doubled.
- Dashboard: conditional polling (ETag and 304), a repository summary view,
  no polling while the tab is hidden, focus and typing kept across polls,
  keyboard-openable rows, higher-contrast colours.
- API: weak ETags and 304 on JSON views, `Vary` on the field-name opt-in, and
  `GET /api/repos?view=summary`.
- Docs describe the Argo-native admission model; size grants now only gate
  automatic tag priority. `docs/mcp-setup.md` again carries the v0.20.3 text
  on client deadlines and hold servicing, which v0.21.0 dropped by mistake.

## Upgrade notes

1. `oberth upgrade --yes` with the v0.21.1 CLI.
2. Scripts that parse `oberth runs --json` as an array, or expect `oberth
   issues` to print everything, need the new shape or `--all`.
3. A token file in `~/.config/oberth` without an `env` or `mcp.json` that
   names its server is no longer picked up automatically; pass `--token-file`
   or run `oberth client setup`.

## Rollback notes

- `oberth upgrade --rollback <record> --yes` returns to v0.21.0. No migration
  ran, so no restore is needed.

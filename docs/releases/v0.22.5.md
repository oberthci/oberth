# v0.22.5


## Install planning

Install plan makes no cluster mutations. It reports that the NetworkPolicy
enforcement check will run first at install, after approval. Install always
runs a fresh measurement before release changes and refuses fresh installs
when enforcement is absent or unverified. Cleanup of probe Pods and their
scratch namespace, restricted Pod Security, explicit probe container selection
and UID checks remain in place.
Plan measurement receipts and their reuse have been removed.

JSON apply failures retain the measured enforcement status, evidence and cleanup
remedy, including the scratch namespace when cleanup fails.


## Argo controller configuration

Oberth no longer attests the Argo controller image, process, ConfigMap or Pod
history. Dispatch no longer waits for controller-profile verification. The
profile flags, chart settings, status fields, metric and dashboard notices are
removed. The nonroot template annotation and preparation container remain.

Operators can use native controller configuration such as `artifactDrivers`,
`executor.resources` and `archiveLogs` without the profile allowlist. This does
not add artifact drivers or replace Oberth's existing log collection.

Global and namespace run caps belong to Argo Helm `controller.parallelism` and
`controller.namespaceParallelism`. The installer passes an explicit global cap
directly to Helm and preserves stored operator-set Argo values on upgrades.
Remove `argo.controllerProfile` and `argo.controllerProfileConfigMap` from
Oberth values before upgrading.

An Argo release installed with the old profile needs an explicit values migration:
`--reuse-values` retains `controller.configMap.create=false`, so setting native
`controller.parallelism` alone has no effect. Export the release's user values
with `helm get values argo-workflows -n <argo-namespace> -o yaml`, retain the
complete file, and review these profile-owned entries:

- Remove `controller.configMap.create` and `controller.configMap.name` to restore
  the chart's native ConfigMap. Record the old name before removing it.
- Remove only the `oberth-controller-profile` entry from `controller.volumes` and
  `controller.volumeMounts`; keep every unrelated entry.
- Remove only the old named profile ConfigMap from `extraObjects`; retain other
  operator objects.
- Review `controller.image.tag` and `executor.image.tag`. Remove the former
  profile controller tag to use the chart's controller version. Keep the executor
  tag when it equals `v4.0.8@sha256:86a965d7eea176959351156e24f3a2fa8d8e342e477ef425009af95a12e3fe87`.
  The managed installer now sets that required executor pin independently of the
  deleted profile. An incompatible stored executor image is left unchanged and
  installation refuses with the required image, rather than replacing it.

Apply the complete reviewed values file to the separate Argo release using
`helm upgrade argo-workflows argo/argo-workflows -n <argo-namespace> --version 1.0.24 --reset-values --values <reviewed-values.yaml>`.
Include the desired native `controller.parallelism` and
`controller.namespaceParallelism` in that file, or rerun the managed installer
with `--argo-parallelism` afterward. Merely omitting keys from an override file
while retaining `--reuse-values` does not unset stored values. Oberth does not
automatically delete the old profile values or unrelated operator settings.

The nonroot patch still targets main and Argo's known init/wait containers.
Operator controller `templateDefaults`/`workflowDefaults` sidecars and init
containers are outside that hardening. A different Argo version that produces
incompatible Pod shapes fails closed at Pod creation, without a dispatch-time
version check; this does not detect every other version or harden operator-added
containers. Qualify changed controllers against the resulting Pods.

Moving helper budgets from Workflow patches to native `executor.resources` is
separate work pending the helper-storage policy removal.


## Trivy cache admission

Oberth no longer refuses unordered Trivy steps that share a cache. Order these
steps with native Argo `depends`, or use a synchronization mutex.

## Secret delivery

The envconsul credential chain is removed. Use `oberth secretstore exec`;
other commands receive no secret-store login token. HCL remains an indirect
dependency of the Vault API client.

## Workflow recovery

Recovery no longer unwraps the retired step observer command or replays helper
storage policies V1-V3 or the unversioned policy. Only the current V4 helper
policy is supported. Drain old in-flight Workflows before upgrading: removed
execution formats are refused during recovery, with no compatibility replay.
The retired execution-annotation refusal list is removed. The executor-token
waiter protections from v0.22.3 are retained; that release already removed the
old waiter.


## Source and artifact helper cleanup

After submission, Oberth binds the source claim and any surviving seed Pod to
the Workflow UID. The existing orphan sweep removes seed Pods left before
Workflow creation or ownership adoption. Artifact collector Pods carry that Workflow owner at creation.
Kubernetes garbage collection removes the helpers with their owner.

Artifact collection stops after two minutes, with up to five additional seconds
for Pod cleanup. A deadline adds "artifact collection deadline exceeded" to the
existing run reason line and audit evidence; Argo's verdict stays unchanged.

Collection replaces a crash-leftover collector only after checking its Workflow
owner and deleting that Pod with UID and resource-version preconditions. Claim
ownership adoption is retried once. Deadline notes survive publication and
publication retries without changing eviction or execution-deadline guidance.


## Server restart recovery

Oberth no longer automatically resubmits claimed runs or retries interrupted
promotions after a server restart. If a run's Workflow is definitely absent,
including work never submitted, the run fails with the reason "interrupted by
server restart". Request another attempt with `run_retry`, `run_rerun`, or
`promote_retry`.

Existing Workflows are adopted and continue under their original run IDs.
Shutdown leaves live Workflows alone. Uncertain creates keep their existing
observation window; recovery adopts a Workflow that appears and fails only
after confirming absence. API errors are not treated as absence.

The forward migration prevents previously queued restart resets from executing
again and restores their prior Workflow names for adoption where available.

# v0.18.0 release candidate

This candidate builds on v0.17.99. It removes Oberth's scheduling harness:
exclusive classes, size weights, declared resource budgets and the head-wait
backfill are gone, and so are their Helm values and server flags. Admission now
counts runs against one optional ceiling and reads nothing from a workflow
document to decide whether a run may start. Shared step limits are native Argo
`synchronization`, passed through as written; the chart renders their limits
from `argoSync.semaphores`; and `releases.serialize` runs releases one at a
time with a native mutex. The minor version moves because values and flags
were removed and admission semantics changed.

**MCP tools: 90 → 90.** No tool is added or removed. `run_get` with
`summary: true`, `run_list` and `/api/runs` rows drop the always-empty `size`
and `declared_resources` fields; the admission observation drops `size`,
`weight`, `numeric_budget`, `backfill_message`, `declared_resources`,
`legacy_resources` and `exclusive_*`; `admission_release` drops `weight`.

## Admission counts runs

- **One optional ceiling.** `maxConcurrentJobs` (`--max-concurrent-jobs`) is
  the number of runs that may hold a Workflow at once, 0..64. The default is
  `0`: no ceiling. The runtime override (`admission_capacity_config`, the
  mounted ConfigMap key) accepts `0` with the same meaning. `used`/`capacity`
  and `runs`/`max_runs` in the admission observation and system status are the
  same two numbers.
- **Nothing in a document is weighed.** The in-process gate no longer has
  size weights, a numeric CPU/memory budget, fixed per-size charges, an IO
  run ceiling, a head-wait origin or backfill. `oberth.ci/size` is still
  accepted and still records nothing admission uses.
- **Kept, because they read the host and not the workflow:** the PSI hard
  valve (`admission.pressure.*`), the disk floor (`admission.diskFloorBytes`),
  the administrator hold, the startup stall bound (`admission.stallTimeout`)
  and the step start-up allowance.
- **Kept, declared in the document:** repository concurrency groups
  (`oberth.ci/concurrency-group`), unchanged; their MCP tool, CLI view and
  store contract are in use. Automatic tag priority is no longer capped by a
  size tier; `size_grant` remains the release-priority policy record it
  already was.
- **Reason lines.** The queued reason for a full ceiling stays `N of M runs
  running`; a head waiting for a slot reads `waiting for a run slot` or
  `1 run running`; `exclusive <class> busy` is gone. The dashboard capacity
  card shows `N/M run slots used` or `no run ceiling`. No status, label or
  layout is added.

## Native synchronization passes through

- `synchronization` at workflow or template level, semaphores by
  `configMapKeyRef` and mutexes by name, is admitted and submitted exactly as
  written. The refusal of ConfigMap semaphores, database locks and
  `namespace` overrides and the `<trigger>/<repo>/` mutex rewrite are
  removed: there is no content filter, and a CI and a release pipeline that
  name the same mutex now share it.
- The chart renders `argoSync.semaphores` (default empty) into the ConfigMap
  `oberth-sync-limits` in the pipeline namespace. The installer's
  single-namespace Argo controller Role already grants `configmaps`
  get/list/watch there, so the controller reads and watches it without an
  RBAC change. Keys are ConfigMap keys; values are positive integers.
- A Workflow or step that Argo holds behind a lock is exempt from
  `admission.stallTimeout`, and the pre-start watchdog does not count a
  workflow-level lock wait: both follow Argo's `startedAt`.
- The reason line names the lock: `waiting for lock
  ConfigMap/oberth-sync-limits/kvm (0/1 free)`, only when the controller's
  key matches `<ns>/<ConfigMap|Mutex|Database>/<name>[/<key>]`; otherwise
  `Waiting for lock (synchronization).`
- A held retry keeps its template lock (Argo takes template locks on the
  retry parent before attempt 1); `TestBuildAssistHoldKeepsTemplateSynchronization`
  pins that `Build` leaves the lock on the template it gives the hold.
- See [admission and native synchronization](../native-synchronization.md).

## Serialized releases

`releases.serialize: true` (`--serialize-releases`, default `false`) adds the
native Argo workflow-level mutex `oberth-release` to every release run of every
repository at submission, so no two releases run at the same time. The
decision is the run's trigger, not its document; a document's own workflow-level
`synchronization` is merged, not replaced. A waiting release is Pending with
`waiting for lock Mutex/oberth-release (0/1 free)` and is not a stall.
Release runs never hold (the retry hold is branch-only), so nothing changes for
the hold. No earlier release-exclusion mechanism existed; release priority only
ordered the queue.

## Security

- A semaphore reads one integer from a ConfigMap key in the run's namespace
  through the Argo controller's RBAC; no ConfigMap content reaches a Pod
  through `synchronization`. A `namespace` override can only name a ConfigMap
  the controller's Role can read, which for the installer's single-namespace
  controller is the pipeline namespace.
- A mutex is a name. Naming another repository's lock delays it, bounded by
  the holder's `activeDeadlineSeconds`, and the reason line shows which lock.
  Shared concurrency groups allowed the same.
- The lock key is the only controller text admitted into a reason line, and
  only as `<Kind>/<name>[/<key>]` over `[A-Za-z0-9_.-]`.
- `ARGO_*` environment names are still refused from repository YAML. This is
  the one content check kept for the retry hold's safety (the hold is driven
  by `ARGO_DEBUG_PAUSE_BEFORE`); it is not scheduling.
- Removed content checks: `oberth.ci/exclusive` validation and allowlist,
  `synchronization` refusals and mutex scoping, size-grant authorization of a
  document's size tier, declared Pod demand against a numeric budget.

## Upgrading from 0.17.x

1. **Back up the database first**, as always. This release adds no migration;
   the `admission_head_waits` table stays in the schema and is no longer
   written.
2. **Removed Helm values.** Each is still accepted at exactly its former stock
   default, so a `helm upgrade --reuse-values` from a stock 0.17.x install
   renders; any other value fails `helm upgrade` with a message that names
   the removal and its replacement. Remove the keys from your values file;
   nothing replaces them except where noted.

   | Removed value | Removed flag | What to do |
   | --- | --- | --- |
   | `admission.exclusiveClasses` (empty renders; any class fails) | `--admission-exclusive-classes` | Define limits in `argoSync.semaphores`; steps declare the native semaphore (below). |
   | `admission.sizeWeights` (S 1, M 2, L 3, XL 0 renders; anything else fails) | `--admission-size-weights` | Nothing. Pods are placed by their `resources`. |
   | `admission.declaredResources.*` (stock defaults render; anything else fails) and the per-size charge map beside it (empty renders) | `--disable-declared-admission`, `--admission-cpu-millis`, `--admission-memory-bytes`, `--admission-memory-headroom-bytes`, `--admission-memory-headroom-percent`, `--admission-io-runs`, `--admission-extended-resources` and the per-size charge flag | Nothing. |
   | `admission.maxHeadWait` (`20m` renders; anything else fails) | `--admission-max-head-wait` | Nothing. |
   | `admission.pressure.{cpuSomeAvg10,ioSomeAvg10,maxWaitSeconds,mode,ioFullAvg60Max,cpuSomeAvg60Max,hysteresis,maxDefer}` | `--admission-pressure-cpu-some-avg10`, `--admission-pressure-io-some-avg10`, `--admission-pressure-max-wait-seconds`, `--admission-pressure-mode`, `--admission-pressure-io-full-avg60-max`, `--admission-pressure-cpu-some-avg60-max`, `--admission-pressure-hysteresis`, `--admission-pressure-max-defer` | Nothing; the hard valve (`enabled`, `hardCpu`, `hardIo`) is unchanged. The chart schema still lists these keys as ignored, so a stock values file keeps rendering. |

   A release that set any of these on purpose (for example
   `admission.exclusiveClasses` with classes, or `sizeWeights.XL: 8`) fails
   the upgrade until the key is removed; pass the cleaned values file with
   `-f` instead of reusing.
3. **`maxConcurrentJobs` default changed from 3 to 0 (no ceiling).** An
   install that relied on the chart default now admits every run; set
   `maxConcurrentJobs: 3` explicitly to keep the old behaviour. A value set in
   the values file is unchanged. The schema minimum is now 0.
4. **Step limits move to native semaphores.** Repositories whose steps carry
   `oberth.ci/exclusive: kvm` or `oberth.ci/exclusive: heavy-go` keep running
   after the upgrade: the annotation is accepted and ignored, so those steps
   no longer wait for each other until the document changes. Define the limits
   once:

   ```yaml
   argoSync:
     semaphores:
       kvm: 1
       heavy-go: 2
   ```

   and on each such template replace the annotation with the semaphore:

   ```yaml
   # before
       - name: kernel-matrix
         metadata:
           annotations:
             oberth.ci/exclusive: kvm

   # after
       - name: kernel-matrix
         synchronization:
           semaphores:
             - configMapKeyRef:
                 name: oberth-sync-limits
                 key: kvm
   ```

   `heavy-go` is the same with `key: heavy-go`. A semaphore on a template that
   also uses the retry hold is kept for the whole hold.
5. **`releases.serialize`** is new and off. Set it to `true` to run releases
   one at a time across all repositories; the Deployment then carries
   `--serialize-releases=true`.
6. The Deployment loses the `--admission-exclusive-classes` argument and
   changes the `--max-concurrent-jobs` default, so it rolls once.
7. MCP clients that pin the tool list still see 90 tools; clients that read
   `size` or `declared_resources` from run rows see the fields gone.

## Rollback notes

- No migration was added, so a v0.17.99 server opens the database as is.
- Remove `argoSync` and `releases` from the values file before installing the
  v0.17.99 chart, whose schema does not know them, and set
  `maxConcurrentJobs` to 1..64 (v0.17.99 refuses 0). The v0.17.99 binary does
  not know `--serialize-releases`.
- v0.17.99 refuses `synchronization.semaphores[].configMapKeyRef` at
  admission and scopes mutex names again; a document migrated to the native
  semaphore is refused by the older server until it is reverted, and a
  release run adopted with the `oberth-release` mutex keeps it until it ends.
- v0.17.99 refuses the `oberth.ci/exclusive` annotation unless its class is on
  `admission.exclusiveClasses`; restore that value before rolling back if the
  documents still carry the annotation.
- The ConfigMap `oberth-sync-limits` is Helm-owned and removed with the value.

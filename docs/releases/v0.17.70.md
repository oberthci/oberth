# Oberth v0.17.70

- Ordinary database reads use a bounded, read-only WAL connection pool, keeping
  repository/upstream resolution, run status and list queries independent of
  the single writer connection. Authentication and upgrade queue sampling
  retain their dedicated reader pools.
- Step timing batches validate and encode inputs before opening the write
  transaction, validate each run's Workflow graph once per transaction and
  count retained timing rows once per run. Batches retain atomic rollback,
  attempt identity checks and completed timing immutability.

This update follows [v0.17.69](v0.17.69.md) and adds no database migration or
required configuration. Deployments upgrading from an earlier release should
also follow the v0.17.69 migration and VM workflow drain guidance.

Audit verification retains its writer-bound cache trust check and final fence.
Unrelated writes can still cause bounded verification retries; see
[audit verification cache](../audit-verification-cache.md). The reader pool
does not remove SQLite's single-writer limit.

Release binaries and packaged charts continue to derive their versions from
the release tag.

# v0.22.0

Oberth submits validated runs to Argo without resource admission. Argo owns the
Workflow queue; Kubernetes owns Pending Pods. See [native scheduling](../native-scheduling.md).

## Action required: semaphore ConfigMap ownership

The installer no longer renders or manages `oberth-sync-limits`.
Existing installations keep the ConfigMap with identical semaphore data as an
operator-owned object: upgrade removes Helm ownership and marks it `keep`
before Helm runs, so this and later upgrades leave it alone.
`--argo-sync-limit` is removed. New installations create no semaphore ConfigMap;
create one with kubectl before running Workflows that use semaphores. A missing
ConfigMap fails in Argo. For example:

```yaml
apiVersion: v1
kind: ConfigMap
metadata:
  name: oberth-sync-limits
  namespace: oberth-argo
data:
  kvm: "1"
  heavy-go: "2"
```

On a new installation, apply this with `kubectl apply -f semaphore-limits.yaml`.
For an existing installation, keep and maintain its actual keys and values; no
recreation is required.
Oberth's own build/release YAML has no semaphore ConfigMap references. Its
`oberth-chart-index` and `oberth-release-finalize` locks are named native Argo
mutexes that protect their specific publication mutations.

## Removed controls

CPU pools/reservations/live credits/capacity monitors, fair share/backfill and
preparation lookahead, PSI admission, resource/size grants, queue caps and active
receive deferrals, disk-floor and admin holds, startup stalls/allowances and
Oberth deadline defaults/caps are gone. Requests, compute limits, affinity,
parallelism, retry policy, synchronization and priority belong in repository
Argo YAML. Requests and deadlines are optional. Generic node-capacity expiry is
removed; impossible placement stays Pending under native policy.

Removed serve flags include `--admission-cpu-enabled`,
`--admission-cpu-headroom-percent`, `--step-cpu-request-percent`, all
`--admission-pressure-*`, `--admission-disk-floor-bytes`,
`--admission-stall-timeout` and `--admission-step-startup-allowance-*`.
The complete `admission` chart block is removed. Deleted flags/values and
removed grant/hold/cap tools produce errors. For stored release values, follow
`oberth upgrade`'s explicit `--set admission=null` instruction; delete the block
from supplied values files. Directly setting an unknown removed value on a
fresh chart, including an otherwise-unmatched null, is an error.

No user Workflow receives an Oberth pipeline PriorityClass or preemption policy.
The class **object remains for this release**, because v0.21.10 Workflows still
running during upgrade reference it when creating later Pods. Removing it now
would make those Pod creates fail. Source/executor helper Pods retain their
class. The object is a removal candidate in the following release after old
Workflows finish. Argo and optional secret-store installation remain. Oberth removes the extra
100m/128Mi requests and control-plane priority class it installed on those two;
their own chart defaults apply. A secret-store StatefulSet with OnDelete takes
up this change only when its Pod is next recreated. The server Deployment
keeps its control-plane class.

## Action required: authored retry policy

Oberth no longer automatically retries infrastructure failures. Declare native
Argo retryStrategy where the steps need it; manual run_retry/run_rerun stay.
For example:

```yaml
retryStrategy:
  limit: "2"
  retryPolicy: OnError
```

This repository's step retry policies are authored in `.oberth/*.yaml`.
No deadline is required. If a Pod can never be placed and the Workflow has no
deadline, it holds a global slot until an operator cancels it.

## TEMPORARY DEVIATION: unbounded source delivery

Source delivery is unchanged until separately tracked native source delivery
replaces it. Every active accepted run retains a
full server checkout and cluster source volume while it waits in Argo. Promotion
workspaces and pinned exports add more server data. There is no
Oberth count bound. With N active runs and Argo parallelism P, up to N seed Pods
and N source PVCs can be created concurrently. Seed Pods run before their
Workflow exists and outside Argo parallelism. A seed Pod may remain Pending
without a start timeout; cancellation or supersession cleans its Pod and PVC. There is no automatic infrastructure retry; use a
manual run retry. Argo retryStrategy cannot retry source preparation before the
Workflow exists.
The ordinary seed does not inherit authored Workflow node selectors, affinity
or tolerations. Its ReadWriteOnce source volume binds on the seed's node/storage
topology and ties the run's later Pods there; incompatible authored placement
stays Pending on a multi-node cluster. This is part of the source deviation.
A full server disk fails work rather than pausing submissions. Native source delivery is tracked separately.

## Step usage figures removed

Per-step CPU and memory usage figures and run_resources (oberth run resources)
are gone in v0.22.0, together with repo_usage, the external sampler, command
wrapping, usage executable mounts and Oberth-added architecture selectors.
Usage may return later from Kubernetes metrics. Authored requests and limits
remain unchanged; the static YAML resource guard stays.

Upgrade drops sampled usage rows, resource-report attempt/disposition history
and historical step CPU/RSS/memory counters and size labels. Run outcomes, log
ranges, timestamps, termination diagnostics and audit history remain. Restore
from the pre-upgrade backup if that removed history is needed.

Remove argo.resourceSampler from supplied values and drop a stored value with
--set argo.resourceSampler=null. The argo-resource-sampler-config serve flag
and execution-target resource_sampler setting no longer exist.

## Upgrade and operation

Take and verify the pre-upgrade database backup before changing the server.
The following boundaries apply to work in flight:

- Ordinary already-submitted Workflows retain their exact UID, source and
  execution bindings and are adopted without rebuilding their submitted spec.
  This includes ordinary measured Workflows from the previous server and native
  suspended Workflows. Native resume, suspend, stop and terminate remain usable
  after restart; they do not change execution authority.
- A Workflow submitted under a grant containing a device map can recover its
  original capability hash only through the migration receipt for that exact
  in-flight run, Workflow and SHA. The current API-kind/action grant and identity
  must remain unchanged. A genuine grant change or other binding refusal fails
  that run with a reason naming its Workflow; it does not stop recovery of other
  runs or scheduler startup. The refused Workflow is left for operator
  inspection, without automatic deletion or resubmission. An unavailable
  Workflow read remains a startup error.
- Before upgrading, finish or cancel **all active assisted Workflows created by
  the previous server**, including those not currently held: their later retry
  Pods still use the old helper mount. The new server uses
  `/run/oberth/assist/oberth`; old held Pods carry `/run/oberth/usage/oberth` and
  cannot be patched through the new API. Continue may depend on an image-provided
  `touch` command. Service their holds with the old owner, or cancel and rerun
  after upgrading. An empty hold list alone does not prove an assisted Workflow
  has finished.
- Existing uncertain-create and cancellation obligations keep their bounded,
  UID-checked cleanup path. They are not reconstructed as new submissions under
  an old measured spec. Drain retired technology-specific executions and clean
  their external resources with the old owner as described in the
  [capability migration guide](../workflow-capabilities.md#migration-from-retired-execution).
  Ordinary unassisted running or native suspended Workflows need no drain.

Check for active assisted Workflows in every execution namespace before the
upgrade, using the old server to service or cancel each listed run, and repeat
until none are listed:

```sh
kubectl -n oberth-argo get workflows -o json | jq -r '
  .items[]
  | select(.metadata.annotations["oberth.ci/assist"] != null)
  | select(.status.phase != "Succeeded" and .status.phase != "Failed" and .status.phase != "Error")
  | [.metadata.name, .metadata.annotations["oberth.ci/run-id"], (.status.phase // "Pending")]
  | @tsv'
oberth run hold list <run-id>
```

Remove the seven execution-target placement fields from operator files:
`node_name`, `node_uid`, `provider_id`, `zone`, `pool`, `taint_key` and
`taint_value`, including null values. Stored executor snapshots are migrated;
operators must update their input files and put intended selectors, affinity
and tolerations in repository YAML, with Kubernetes policy enforcing any node
isolation. Cluster, namespace and identity custody remain. See
[execution targets](../execution-targets.md).

Remove `extended_resources` from capability grant files. New device and other
extended-resource requests use vanilla Kubernetes resources; operators enforce
them through ResourceQuota and admission policy. API-kind/action capability
grants still apply to resource templates. See
[extended resources](../workflow-capabilities.md#extended-resources).

Forward migrations remove fair-share indexes and retired admission tables.
Accepted deferred receives become ordinary run records; ref-deleted receipts
become terminal cancelled records that remain bound to their event IDs. Replay
does not resurrect them or hide a recreated same-SHA branch. Existing queued
runs proceed under the new submission rules. Old admission annotations do not
reinstate policy. Historical usage figures and size labels are dropped as
described [above](#step-usage-figures-removed); outcomes, logs, timestamps,
termination diagnostics and audit remain. Rollback, or recovery of those usage
figures, requires the verified pre-upgrade database backup.

`--argo-parallelism 0` means unlimited, as before. Fresh-install cap defaults are
unchanged. Pause by scaling the workflow-controller to zero replicas or using
`argo suspend` for a Workflow. Supersede, branch-delete cancellation, explicit
cancel/retry/rerun, assisted holds, publication, secret and identity custody stay.
Automatic infrastructure retry is removed; authors choose retryStrategy. A
Workflow without a deadline whose Pod can never be scheduled holds a global
Argo slot until cancelled. The plugin install flow is delivered separately.


## Controller verification status

The existing authenticated controller-profile wait is named `dispatch_blocked`
in `controller_profile`. Its metric is `oberth_controller_verification_blocked`.
It verifies controller identity and readiness; it does not inspect resources,
pressure or capacity. Update consumers of the former admission-pause names.
No alias is exported.

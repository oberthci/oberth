# v0.22.0

## Plugin installation

- IP-only and load-balancer endpoints get a proposed DNS name, exact hosts/DNS
  instructions and a name re-probe before installation continues (#1544).
- Managed clusters can use a reviewed LoadBalancer Service. Address discovery
  waits within a fixed bound and retains the approved hostname and client ports;
  the wait creates no Service before install Review (#1545).
- Missing kind port mappings produce a complete loopback mapping configuration
  and guarded create command using a separate new kubeconfig. Existing files,
  symlinks and the selected cluster are preserved (#1546).
- On macOS with Homebrew, missing kubectl or Helm gets an exact install command.
  The wrapper only prints hints and stops; it never runs brew (#1547).
- Removed automatic cluster creation and the related CLI/TUI path. Existing
  operator-created clusters remain valid targets; kind remedies are instructions
  for the operator, not commands Oberth executes (#1553).
- NetworkPolicy capability uses live egress-only denial and recovery with a
  concurrent control path and explicit namespace/node scope. Ambiguous traffic
  or slow convergence is unverified; expired owned probes reconcile next run.
  Existing-release maintenance discovers and preserves the stored choice first;
  unverified capability is informational, while fresh install/explicit verify
  stay fail-closed. Namespace cleanup binds the observed UID and version and
  preserves replaced or unknown-lifetime objects (#1548).
- Native kubeconfig reads disable migration; kubectl and Helm helpers receive
  owner-only private merged copies through flags and environment, including
  setup and add-repo. Leased ownership-marked copies are swept at the next
  startup after their last lease holder exits; handled signals include SIGQUIT.
  Exec credential plugins may keep their own caches (#1549).

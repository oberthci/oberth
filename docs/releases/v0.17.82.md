# Oberth v0.17.82 candidate

This candidate builds on v0.17.81. It contains the reviewed chart, installer,
Git, admission reporting and executor repairs described below.

## Chart and release contracts

- Enabling the Go proxy preserves server SSH and HTTPS ingress. Pipeline pods
  can reach this release's proxy listener without gaining server SSH or HTTPS
  egress. Network policies follow a custom proxy port.
- CI secret-store verification can request short-lived tokens only for the
  configured per-repository CI identities, through a dedicated Role.
- Rotating the Rekor or TSA CA changes the server Pod template checksum.
- The Argo values schema rejects unknown fields and invalid sampler settings.
  Explicit empty CI secrets service-account and role strings are rejected;
  omit those keys to use their defaults. Retired compatibility keys remain
  declared for upgrades that reuse values, including the ignored boolean
  `argo.enabled` setting.
- The Make test targets invoke the current native Git gate. The release prune
  regression requires the signed release manifest and its bundle.

## Installer and Git repairs

- Both secret-store setup scripts detect absent mounts using checked OpenBao
  inventories. Failed inventory, policy or role reads abort instead of being
  treated as missing configuration, including when force options are used.
- Plain upgrades and dry runs without TLS changes do not require an OpenBao
  token. An unreadable served certificate warns during additive repair;
  certificate-name removals still require a readable leaf and fail closed.
- TLS overrides are pinned to the explicit reconciliation flags only when the
  deployed release uses PKI. A non-PKI release keeps its ordinary value overrides.
- Upstream branch deletion records a deleted event only after its audited
  mutation succeeds. Retried deletion remains idempotent.

## Admission and executor repairs

- Usage, fit and reservation reports use the same memory charge, including
  configured headroom. Numeric CPU and memory blockers prevent later backfill
  from consuming the head's required capacity.
- Measured EASY backfill replaces the v0.17.81 guard behind priority heads.
  The reservation rule below applies to every priority class.
- Failed head-wait persistence is retried while writes remain pending.
- Executor resource-create gating includes release work. Secret input accepts
  newline-only values and reports invalid input paths without printing values.
- Artifact scanning shares the streaming redactor. Image registry validation
  recognizes slashless registries and ports and rejects invalid image names.

## EASY admission backfill

EASY replaces v0.17.81's conservative ban on backfill behind high/highest
admission heads. Later work that fits current capacity can backfill when its
measured p95 duration ends strictly before the head's estimated start. Equal
or longer durations do not pass this test. The rule also applies while the
queue reports draining after the default 20-minute head wait.

Work in the same effective and base priority class may also backfill if the
head still fits alongside it at its reserved start. Lower classes cannot use
this coexistence exception, even when their resource requests fit beside the
head. Candidates without enough duration samples can use only same-class
coexistence. All surviving grants count toward the projected resource and run
ceilings. Repository concurrency groups, VM capacity, host pressure, disk
floors and existing resource protections continue to apply. Setting
`--admission-max-head-wait=0` retains strict FIFO.

Forecasts use the newest 30 passed runs of the repository's workflow class
(branch, release, promotion or schedule), requiring at least five distinct
complete samples. Whole workflow durations include retained step observations
and known startup/teardown. When all observations for a run have been pruned,
its durable start and finish timestamps preserve the sample. Incomplete
observations and truncated history do not supply an estimate.

Admission views report backfilling or draining for every head priority and
explain whether a candidate ends before the reserved start or would delay it.
A head's forecast cannot move later while it remains head; changing heads
resets that forecast. P95 values remain estimates, not enforced runtime
limits, and overruns can delay the head. Running work is not preempted.

This update requires no database migration or resource configuration change.
See [release priority and fairness](../release-priority.md) and
[admission waits](../ob-admission-wait-report.md) for details.

## Upgrade and qualification

This candidate adds no migrations to the v0.17.81 ledger, which ends with
priority submissions at version 39. The integration and restart replay are
held for their review and migration prerequisites. Their reserved release order
remains token expiry, issue revision and publication abandonment at 40–42,
restart timing and tag publication identity at 43/44, then staged retirement
and capability changes at 45–47. No placeholder migrations are installed.

Local tests cannot establish live network-policy enforcement, PKI repair,
restart recovery or queue throughput. The release still requires CI and live
upgrade qualification.

# Oberth v0.17.82

## EASY admission backfill

EASY replaces v0.17.81's conservative ban on backfill behind high/highest
admission heads. Later work that fits current capacity can backfill when its
measured p95 duration ends strictly before the head's estimated start. Equal
or longer durations do not pass this test. The rule applies to every priority
class, including while the queue reports draining after the default 20-minute
head wait.

Work in the same effective and base priority class may also backfill if the
head still fits alongside it at its reserved start. Lower classes must finish
before that start and cannot use coexistence. Candidates without enough
duration samples can use only same-class coexistence. All surviving grants
count toward projected resource and run ceilings. Repository concurrency
groups, VM capacity, host pressure, disk floors and existing resource
protections continue to apply. Setting `--admission-max-head-wait=0` retains
strict FIFO.

Forecasts use the newest 30 passed runs of the repository's workflow class
(branch, release, promotion or schedule), requiring at least five distinct
complete samples. Whole workflow durations include retained step observations
and known startup/teardown. When all observations for a run have been pruned,
its durable start and finish timestamps preserve the sample. Incomplete
observations and truncated history do not supply an estimate. Unknown or
already overrun running work is never assumed to release capacity.

Admission views report backfilling or draining for every head priority and
explain whether a candidate ends before the reserved start or would delay it.
A head's forecast cannot move later while it remains head; an expired forecast
stops new backfill until that head starts. Changing heads resets the forecast
while retaining the durable wait origin. P95 values remain estimates, not
enforced runtime limits, and overruns can delay the head. Running work is not
preempted.

See [release priority and fairness](../release-priority.md) and
[admission waits](../ob-admission-wait-report.md) for details.

## One Pod volume per run claim

Source checkouts and step artifacts now share a single Pod volume for the
run's PersistentVolumeClaim, mounted through separate subPaths. Earlier
releases, including v0.17.81, declared the same claim twice (one source and
one artifacts volume). On single-node local-path style storage with
ReadWriteOnce claims, kubelet could stall mounting the second volume, so the
generated Pods never started. Source inputs, the CA bundles and executor
mirrors stay read-only subPath mounts; `/work/artifacts` stays writable;
authored mounts that reuse the reserved names are still removed. Every
seeded run renders the new volume layout.

## Chart and release contracts

- Enabling the Go proxy preserves server SSH and HTTPS ingress. Pipeline pods
  can reach this release's proxy listener without gaining server SSH or HTTPS
  egress. Network policies follow a custom proxy port.
- CI secret-store verification can request short-lived tokens only for the
  configured per-repository CI identities, through a dedicated Role.
- Rotating the Rekor or TSA CA changes the server Pod template checksum.
- The Argo values schema rejects unknown fields and invalid sampler settings.
  Explicit empty CI secrets service-account and role strings are rejected;
  omit those keys to use their defaults. Retired compatibility keys remain
  declared for upgrades that reuse values, including the ignored boolean
  `argo.enabled` setting.
- The Make test targets invoke the current native Git gate. The release prune
  regression requires the signed release manifest and its bundle.
- Build and release workflow containers declare at most 4 CPU and 8Gi memory.
  Release tests and builds bound Go workers and serialize packages; release
  tests retain the full race suite. Resource requests are unchanged. CI must
  confirm release duration and memory peaks under these limits.

## Installer and Git repairs

- Fresh unattended installs require an explicit `--install-secretstore`, or
  `--install-secretstore-dev` for evaluation. Re-running install preserves the
  existing OpenBao connection and PKI mode.
- Both secret-store setup scripts detect absent mounts using checked OpenBao
  inventories. Failed inventory, policy or role reads abort instead of being
  treated as missing configuration, including when force options are used.
- Plain upgrades and dry runs without TLS changes do not require an OpenBao
  token. Install and upgrade preserve existing server certificate DNS names
  and IP SANs. Add names with `--tls-extra-dns-name` or `--tls-extra-ip`;
  removals use `--tls-remove-dns-name` or `--tls-remove-ip` and are refused while
  the served certificate still contains the name. An unreadable served
  certificate warns during additive repair; removals require a readable leaf
  and fail closed.
- TLS overrides are pinned to the explicit reconciliation flags only when the
  deployed release uses PKI. A non-PKI release keeps its ordinary value overrides.
- Default-branch deletion is refused by receive hooks and direct upstream
  deletion, including when the default branch cannot be determined. Upstream
  branch deletion records a deleted event only after its audited mutation
  succeeds. Retried deletion remains idempotent.

## Admission and executor repairs

- Usage, fit and reservation reports use the same memory charge, including
  configured headroom. Numeric CPU and memory blockers prevent later backfill
  from consuming the head's required capacity.
- Head-wait writes are coalesced without losing generation boundaries or the
  original wait time; failed persistence is retried while writes remain pending.
- Credentialed and release work waits for the access reconciler's initial
  successful read. Ordinary uncredentialed branch work can proceed while it
  is unhealthy.
- Artifact collection scans every complete member for configured secrets before
  writing any member, including beyond the old scan ceiling and across newlines.
  Matching collections are refused. Streaming log redaction masks multiline
  values; secret input accepts newline-only values and reports invalid input
  paths without printing values.
- Runner image prefixes match registry and repository boundaries. Registry
  validation recognizes slashless registries and ports and rejects invalid
  image names.

`oberth secretstore exec` now refuses to start the child process when any
fetched key value is 1 or 2 bytes long after trailing newlines are removed:
such values cannot be masked safely in output. v0.17.81 registered them as
masking patterns, which garbled unrelated output. Move short non-secret
settings (for example `enabled=1` or `port=80`) out of release secret paths
before upgrading.

## Retention test repair

The resource-retention regression checks the exact surviving suffix in
observation-time and row-ID order. A deadline can arrive after SQLite commits
one delete batch but before the driver acknowledges it, so the test derives
progress from persisted rows and bounds any unacknowledged batch. Production
retention behavior is unchanged.

## Upgrade from v0.17.81

This release adds no database migrations to v0.17.81's schema version 39 and
requires no resource configuration change for EASY. Retain a verified backup
and its private key before upgrading, and check rollout, schema version,
admission messages and representative queued work before relying on increased
concurrency. See [backup and restore](../backup-restore.md).

Memory admission retains v0.17.81's accounting: concurrent memory requests,
executor allowances and max(1Gi, 10% of declared run memory) headroom. Review
unmeasured memory requests, especially low requests paired with high limits,
before relying on higher concurrency. Containers without complete requests or
positive memory limits retain legacy size admission; workflow resources are
not rewritten. See [declared resources](../declared-resources.md).

Enabled host pressure admission still enforces when reused values set legacy
`admission.pressure.mode: observe`; startup logs warn about that setting. Set
`admission.pressure.enabled: false` for budget-only admission. Defaults remain
CPU/IO some avg10 30%/20%, hard starvation limits 50%/40% and a 30-second settle
window. See [host pressure admission](../io-pressure-admission.md).

For upgrades from before v0.17.81, schema migration 39 adds `priority_grants`
and `run_priority_requests` and supersession protection for existing queued or
running high/highest runs. Helm rollback does not undo that migration; reverting
the schema requires restoring a verified pre-upgrade database backup. See the
[v0.17.81 addendum](v0.17.81.md#priority-builds-and-grants).

Local tests cannot establish live network-policy enforcement, PKI repair,
or queue throughput. CI and live upgrade qualification remain required.

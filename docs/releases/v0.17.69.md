# Oberth v0.17.69

- MCP validation and mutation refusals expose actionable public reasons while
  preserving internal error privacy and retryable audit-contention responses.
- Issue append, update and close return compact acknowledgments. Issue reads
  support field selection and UTF-8-safe body limits; `run_get` accepts
  `summary:true` for compact status and step results. Full reads remain the
  default. See [MCP setup](../mcp-setup.md).
- Queue priority orders waiting work by server-owned class and admission FIFO.
  Promotions and authorized tag/release runs take highest priority;
  administrators can configure release-candidate patterns and audit explicit
  priority bumps. Waiting work ages to highest after 60 minutes, while existing
  grants remain in place. See [MCP setup](../mcp-setup.md#queue-priority-administration).
- Opt-in KubeVirt cleanup verdicts gate terminal success on independently
  verified absence of original VMIs, launcher Pods and backing resources.
  Cleanup preserves run and Workflow identity, uses UID deletion preconditions,
  attempts safe sibling cleanup after failures, and publishes a bounded receipt.
  An admitted VMI `get` with `--ignore-not-found` succeeds on absence without
  turning the step red. See [KubeVirt VMs](../kubevirt-vms.md).
- The upgrade-wait process regression now synchronizes on an observed retry
  before cancellation, preserving HTTP 503 diagnostics under slow startup.

This update adds forward-only database migration v34 for queue priority.
Existing deployments start with no release-candidate patterns; no new required
configuration values are added. Drain existing verdict-enabled VM workflows
before upgrading because their older create receipts lack the new identity
binding. Issue mutation callers needing full content should follow the compact
acknowledgment with `issue_get`.

Release binaries and packaged charts continue to derive their versions from
the release tag.

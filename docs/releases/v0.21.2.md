# v0.21.2 release candidate

Oberth is pre-launch: this release deletes compatibility code instead of
keeping aliases or deprecation windows. Every item below is a breaking change;
update clients and stored values with the server. No run status, label,
layout or migration is added.

## Breaking

### Record field names

- The Go-style record names (`ID`, `RepoID`, `Steps`) are gone for good. The
  `X-Oberth-Go-Field-Names` request header, the `go_field_names=1` query
  parameter, `oberth mcp call --go-field-names` and `OBERTH_GO_FIELD_NAMES`
  are removed; the header and parameter are ignored. Responses no longer
  vary on that header.
- A json tag spelled in lowerCamel (`activeDeadlineSeconds`) is sent under
  its snake_case name (`active_deadline_seconds`) only.
- A run record carries its identity as `id` only, and responses about a run
  (logs, artifacts, cancel, rerun) as `run_id` only; the other spelling is no
  longer added. Full run details no longer add top-level `id`/`run_id`.
- The CLI decodes snake_case record names only; any other spelling in a
  response is ignored.

### Tool arguments

- Every tool that selects one run takes it as `id`, the name most tools
  already used. The `run_id` alias is refused (`run_get`, `run_logs`,
  `run_retry`, `run_cancel`, `run_rerun`, `run_hold_*`, `run_continue`,
  `run_purge`, `artifacts`, `artifact_get`, `wait`), `run_resources` takes
  `id` instead of `run`, and `run_priority` and `admission_release` take `id`
  instead of `run_id`.
- `run_resources` no longer takes `resource_only`: every caller receives
  resource advice, which omits the deadline (never zero). The HTTP query
  parameter is ignored.
- Priority classes are exactly `low`, `standard`, `promotion` and `high` on
  every tool, push option, schedule file and grant; `normal` and `highest` are
  refused. Rows stored as `normal`/`highest` by earlier servers read as
  `standard`/`high`.
- `wait` no longer maps trigger `ci` to `branch`; pass `branch`.
- `run_list` and `/api/runs` drop `view=active`; the first page of the default
  view already carries every queued and running run. `oberth runs --active`
  reads that page and prints the non-terminal rows; `--json` prints
  `{"runs":[...]}`.

- Blocking tools take their bound only as `timeout_s`. The `timeout` and
  `timeout_seconds` aliases of `wait`, `promote_status`, `run_wait`,
  `events_wait` and `run_hold_exec` are refused as unknown arguments.
- `secretstore_verify` takes `timeout_s` (default 45, at most 120) instead
  of `timeout`; `oberth mcp call` derives its client deadline from it.
- `queue_cap_config` takes `max_not_started` instead of `maxNotStarted`.

### HTTP collections

- `/api/runs`, `/api/repos` and `/api/grants` always return the MCP object
  (`{"runs": [...], "next_before": N}`, `{"repositories": [...]}`,
  `{"grants": [...]}`); `envelope=1` is gone and arrays are no longer sent.
  The CLI reads the next-page cursor from the body.

### Pipeline annotations

- `oberth.ci/size`, `oberth.ci/size-by-trigger`, `oberth.ci/concurrency-group`,
  `oberth.ci/concurrency-limit` (workflow) and `oberth.ci/exclusive`
  (template) are refused at admission and by `oberth validate`, naming the
  replacement (Pod `resources` blocks; native Argo mutexes and semaphores),
  instead of being ignored. Delete them from `.oberth/*.yaml` before
  upgrading. Every run records size M.

### Status

- `system_status` and `/api/status` report only `queue_cap`; the lowerCamel
  `queueCap` is gone. `queue_cap_config` returns `max_not_started` and
  `not_started` only.

### Upgrade

- `oberth upgrade --allow-retired-execution` is removed, together with the
  retired-execution preflight: the inventory of trusted Workflows and
  Oberth-owned virtual machines and the repository retirement check for
  installations at v0.17.94 or earlier.
- Removed chart values are refused, not stripped or ignored: `gitBackend`,
  `gitcache` (including `gitcache.shadow`), `maxConcurrentJobs`, `argoSync`,
  `trustedTests`, `vm`, `watchTunnel`, `secretCreatePolicy`,
  `argo.enabled`, `argo.ciServiceAccount`, `argo.ciSecretsServiceAccount`,
  `argo.vault.ciSecretsRole`, `argo.vmLauncherServiceAccount`,
  `argo.containerDiskPrefixes`, `argo.kubevirtCeiling`,
  `auditAnchor.rootsKey`, `upstream.createSecrets`, `upstream.keySecret`,
  `upstream.knownHostsSecret`, `admission.exclusiveClasses`,
  `admission.sizeWeights`, `admission.maxHeadWait`,
  `admission.declaredResources`, `admission.legacyResources`,
  `admission.runtimeCapacity` and the `admission.pressure` values `mode`,
  `cpuSomeAvg10`, `cpuSomeAvg60Max`, `ioSomeAvg10`, `ioFullAvg60Max`,
  `hysteresis`, `maxDefer` and `maxWaitSeconds`. The chart schema refuses them
  at any value, including their former defaults.
- `argo.ciSecrets.serviceAccount` and `argo.ciSecrets.vaultRole` refuse an
  empty string; omit them for the defaults.
- When the stored release values, a `--values` file or a `--set` still sets
  one, `oberth upgrade` stops before any write and names each key with its
  source:

  ```text
  chart schema validation failed: chart values that no longer exist are set:
  maxConcurrentJobs (stored release values), trustedTests (stored release
  values); no upgrade applied. Delete them from any --values file and re-run
  the upgrade with --set maxConcurrentJobs=null --set trustedTests=null (Helm
  drops a null value from the stored release values)
  ```

  Re-running with those flags drops the keys from the stored values for good.
- `oberth install` re-runs and `oberth restore` reuse the installed release's
  values (`--reuse-values`). While those still carry a removed value, both
  refuse before any change, naming the keys and pointing at `oberth upgrade`,
  which drops stored ones and replaces the installed chart's defaults.

## Upgrading

1. Delete the removed annotations from every repository's `.oberth/*.yaml`;
   admission refuses them after the upgrade.
2. Run `oberth upgrade`; if it refuses, re-run it with `--set <key>=null` for
   each key it names.
3. Update scripts and agents that send `timeout`, `timeout_seconds`,
   `run_id` or `run` selectors, `resource_only`, `maxNotStarted`, `normal` or
   `highest`, trigger `ci`, `view=active`, `envelope=1` or the Go-style
   field-name opt-in, and readers of `queueCap`, lowerCamel names or HTTP
   collection arrays.

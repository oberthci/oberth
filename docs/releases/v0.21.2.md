# v0.21.2 release candidate

This candidate builds on v0.21.1. It deletes compatibility code instead of
keeping aliases or deprecation windows (Oberth is pre-launch), and finishes
the server and installer review leftovers: verified chart deployment for
install and restore, rollback records bound to their upgrade, a restore
migration rehearsal, bounded run timing records, more `/metrics` gauges and
tighter admission rules. Every item under Breaking needs clients, pipelines
or stored values updated with the server. No run status, label, layout or
migration is added.

## Breaking

### Record field names

- The Go-style record names (`ID`, `RepoID`, `Steps`) are gone for good. The
  `X-Oberth-Go-Field-Names` request header, the `go_field_names=1` query
  parameter, `oberth mcp call --go-field-names` and `OBERTH_GO_FIELD_NAMES`
  are removed; the header and parameter are ignored. Responses no longer
  vary on that header.
- A json tag spelled in lowerCamel (`activeDeadlineSeconds`) is sent under
  its snake_case name (`active_deadline_seconds`) only.
- A run record carries its identity as `id` only, and responses about a run
  (logs, artifacts, cancel, rerun) as `run_id` only; the other spelling is no
  longer added. Full run details no longer add top-level `id`/`run_id`.
- The CLI decodes snake_case record names only; any other spelling in a
  response is ignored.

### Tool arguments

- `run_get` returns the compact summary by default (identity, queue
  position, superseded, status, failure and compact steps); pass
  `summary:false` for the full record with step diagnostics, retained timing
  and the repository record. Scripts that read the full record from a bare
  `run_get {id}` must add `summary:false`; the current server already
  accepts it.
- `promote` and `promote_retry` take a branch name only: a ref
  (`refs/heads/main`) or an invalid name is refused before anything is
  admitted.

- Every tool that selects one run takes it as `id`, the name most tools
  already used. The `run_id` alias is refused (`run_get`, `run_logs`,
  `run_retry`, `run_cancel`, `run_rerun`, `run_hold_*`, `run_continue`,
  `run_purge`, `artifacts`, `artifact_get`, `wait`), `run_resources` takes
  `id` instead of `run`, and `run_priority` and `admission_release` take `id`
  instead of `run_id`.
- `run_resources` no longer takes `resource_only`: every caller receives
  resource advice, which omits the deadline (never zero). The HTTP query
  parameter is ignored.
- Priority classes are exactly `low`, `standard`, `promotion` and `high` on
  every tool, push option, schedule file and grant; `normal` and `highest` are
  refused. Rows stored as `normal`/`highest` by earlier servers read as
  `standard`/`high`.
- `wait` no longer maps trigger `ci` to `branch`; pass `branch`.
- `run_list` and `/api/runs` drop `view=active`; the first page of the default
  view already carries every queued and running run. `oberth runs --active`
  reads that page and prints the non-terminal rows; `--json` prints
  `{"runs":[...]}`.

- Blocking tools take their bound only as `timeout_s`. The `timeout` and
  `timeout_seconds` aliases of `wait`, `promote_status`, `run_wait`,
  `events_wait` and `run_hold_exec` are refused as unknown arguments.
- `secretstore_verify` takes `timeout_s` (default 45, at most 120) instead
  of `timeout`; `oberth mcp call` derives its client deadline from it.
- `queue_cap_config` takes `max_not_started` instead of `maxNotStarted`.

### HTTP collections

- `/api/runs`, `/api/repos` and `/api/grants` always return the MCP object
  (`{"runs": [...], "next_before": N}`, `{"repositories": [...]}`,
  `{"grants": [...]}`); `envelope=1` is gone and arrays are no longer sent.
  The CLI reads the next-page cursor from the body.

### Admission

- A semaphore's `configMapKeyRef` must name a key of `oberth-sync-limits`
  in the Workflow's own namespace; another ConfigMap, a namespace or a
  database semaphore is refused.
- Every `retryStrategy` (template, `templateDefaults` and `spec`) needs a
  literal `limit` of at most 10; an absent or templated limit is refused.
- A leaf with a template or `templateDefaults` `timeout`, and every leaf of a
  document with a workflow-wide `retryStrategy`, no longer holds for
  assistance.

### Pipeline annotations

- `oberth.ci/size`, `oberth.ci/size-by-trigger`, `oberth.ci/concurrency-group`,
  `oberth.ci/concurrency-limit` (workflow) and `oberth.ci/exclusive`
  (template) are refused at admission and by `oberth validate`, naming the
  replacement (Pod `resources` blocks; native Argo mutexes and semaphores),
  instead of being ignored. Delete them from `.oberth/*.yaml` before
  upgrading. Every run records size M.

### Status

- `system_status` and `/api/status` report only `queue_cap`; the lowerCamel
  `queueCap` is gone. `queue_cap_config` returns `max_not_started` and
  `not_started` only.

### Install, upgrade and restore

- `oberth install` (fresh and same-version `--upgrade`), the kind image
  load, the OpenBao TLS bootstrap image and the Helm upgrade `oberth
  restore` applies deploy only the chart of the signed release, verified
  against the compiled-in key like `oberth upgrade`; the Oberth chart never
  comes from a Helm repository. Without `--chart`, `--image` must be the
  server image the signed record pins. `--chart` stays the unverified
  development override. A CLI older than the installed release reconciles
  with the installed release's verified chart, never its own. `install` and
  `restore` take `--release-dir`, `--release-origin` and
  `--chart-repository`.
- A non-interactive backup (cron, an unattended upgrade) refuses to create
  the backup key; create it with `oberth backup keygen`, and record an
  off-machine copy with `oberth backup key --stored`.
- `argo.controllerProfileConfigMap` without `argo.controllerProfile` fails at
  render time.
- `oberth upgrade --allow-retired-execution` is removed, together with the
  retired-execution preflight: the inventory of trusted Workflows and
  Oberth-owned virtual machines and the repository retirement check for
  installations at v0.17.94 or earlier.
- `oberth upgrade --ownership-handoff` is removed with the connector/site
  ownership handoff check for upgrades from releases before v0.17.83.
- Removed chart values are refused, not stripped or ignored: `gitBackend`,
  `gitcache` (including `gitcache.shadow`), `maxConcurrentJobs`, `argoSync`,
  `trustedTests`, `vm`, `watchTunnel`, `secretCreatePolicy`,
  `argo.enabled`, `argo.ciServiceAccount`, `argo.ciSecretsServiceAccount`,
  `argo.vault.ciSecretsRole`, `argo.vmLauncherServiceAccount`,
  `argo.containerDiskPrefixes`, `argo.kubevirtCeiling`,
  `auditAnchor.rootsKey`, `upstream.createSecrets`, `upstream.keySecret`,
  `upstream.knownHostsSecret`, `admission.exclusiveClasses`,
  `admission.sizeWeights`, `admission.maxHeadWait`,
  `admission.declaredResources`, `admission.legacyResources`,
  `admission.runtimeCapacity` and the `admission.pressure` values `mode`,
  `cpuSomeAvg10`, `cpuSomeAvg60Max`, `ioSomeAvg10`, `ioFullAvg60Max`,
  `hysteresis`, `maxDefer` and `maxWaitSeconds`. The chart schema refuses them
  at any value, including their former defaults.
- `argo.ciSecrets.serviceAccount` and `argo.ciSecrets.vaultRole` refuse an
  empty string; omit them for the defaults.
- When the stored release values, a `--values` file or a `--set` still sets
  one, `oberth upgrade` stops before any write and names each key with its
  source:

  ```text
  chart schema validation failed: chart values that no longer exist are set:
  maxConcurrentJobs (stored release values), trustedTests (stored release
  values); no upgrade applied. Delete them from any --values file and re-run
  the upgrade with --set maxConcurrentJobs=null --set trustedTests=null (Helm
  drops a null value from the stored release values)
  ```

  Re-running with those flags drops the keys from the stored values for good.
  Pass each flag once, for the keys the refusal names: a `--set <key>=null`
  for a removed value the stored release values do not set is refused, since
  Helm would keep that null and the chart schema refuses it.
- `oberth install` re-runs and `oberth restore` reuse the installed release's
  values (`--reuse-values`). While those still carry a removed value, both
  refuse before any change, naming the keys and pointing at `oberth upgrade`,
  which drops stored ones and replaces the installed chart's defaults.

## Server

- Per-run Workflow and step timing records are kept for the newest 2000
  terminal runs and every run evidence retention protects; older ones are
  pruned in bounded passes (milestones and admission episodes stay) and read
  `unavailable=pruned`. `system_status.storage` reports `database_bytes` and
  `timing_pruned`.
- One credential may hold at most 64 blocking calls (`wait`,
  `promote_status`, `run_wait`, `events_wait`) at once; a further call is
  refused immediately, naming the limit and `events_wait run_ids`.
- `/metrics` also exports queue not-started/max/deferred, admission paused,
  database bytes, data free bytes and below-floor, last backup, latest audit
  anchor and earliest admin token expiry.
- `run_hold_patch` and `run_hold_exec` are no longer cut at the CLI's 60 s
  or the server's 3-minute write timeout; both wait for their own bound.
- A scoped uplink's hold action rechecks the repository's upstream inside the
  assist transaction; the hold action gate keeps only runs with an action in
  flight.
- A deferred Workflow deletion now notifies run waiters and prunes the pod
  log journal.
- Every push failure line is one bounded, control-free line naming the
  record ID `oberth outbox` takes; the full error is in the server log.
- JSON views send `Cache-Control: private, no-cache`.
- The Claude Code plugin helper reads `mcpServers.oberth.url`, quotes its
  path, and refusals drop user information from addresses; `ca.crt` must be
  owned by the user and not writable by others.

## Installer and operations

- `oberth upgrade --rollback` binds its record to where the upgrade left each
  release: a release still at the recorded revision is not rolled back, an
  Oberth release the upgrade never reached needs no restore, and a later
  revision is accepted only when Helm history shows nothing but completed
  rollbacks to the recorded one (an interrupted `pending-rollback` is not).
- `oberth restore` holds admission and rehearses the first-start migration
  on a scratch copy before OpenBao is written, and stops with nothing
  changed when it fails; `restore.completed` names the head the restored
  database starts on.
- `metrics.serviceMonitor` (off by default) renders a Prometheus Operator
  ServiceMonitor that scrapes `/metrics` over verified HTTPS with an admin
  bearer token from an operator-created Secret; see `docs/metrics.md` for
  where that token ends up.
- The nonroot Argo controller profile accepts controller placement
  (`nodeSelector`, `tolerations`) in stored argo-workflows values; any other
  stored value is kept only with `--argo-values-reviewed sha256:<digest of
  helm get values -o json>`.
- Removing `platformProtection` also checks the Pod templates of
  Deployments, StatefulSets, DaemonSets, ReplicaSets, Jobs and CronJobs,
  skipping what a checked controller left behind.

## Upgrading

1. Delete the removed annotations from every repository's `.oberth/*.yaml`;
   admission refuses them after the upgrade.
2. Run `oberth upgrade` with a CLI of this release; if it refuses, re-run it with `--set <key>=null` for
   each key it names.
3. Add `summary:false` to scripts that read the full record from `run_get`,
   and check pipelines against the new admission rules (semaphore source,
   retry limits).
4. Update scripts and agents that send `timeout`, `timeout_seconds`,
   `run_id` or `run` selectors, `resource_only`, `maxNotStarted`, `normal` or
   `highest`, trigger `ci`, `view=active`, `envelope=1` or the Go-style
   field-name opt-in, and readers of `queueCap`, lowerCamel names or HTTP
   collection arrays.

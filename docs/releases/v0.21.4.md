# v0.21.4 release candidate

This candidate builds on v0.21.3 and fixes what a fresh-install rehearsal
found: a non-interactive install of v0.21.3 on a new k3s cluster, run by an
AI agent with only kubectl and helm, followed by Claude Code with the Oberth
plugin (#1525, #1521). No run status, label, layout or migration is added.

## Install and CLI

### Breaking

- **Any reachable cluster is a target.** `oberth install`, `oberth setup`
  and `oberth upgrade` no longer classify clusters by API address. The
  "does not appear to be a local cluster" refusal is gone. It refused k3d
  clusters, whose API listens on 0.0.0.0, and spoke of a "dev secret store"
  when a production one was requested. With it go `oberth install --yes` and
  the setup wizard's second "Confirm remote install". The target is the
  kubeconfig context: setup lists the contexts of the selected kubeconfig
  (`--kubeconfig`, else `KUBECONFIG`, else `~/.kube/config`). `oberth install`
  takes `--context` and refuses to pick one itself when there are several.
  Both name the context and its API server before acting (`Target: <context>
  (<server>)`, and the review summary). The review's Install confirmation is
  the only gate.
- `oberth upgrade --yes` applies to `--rollback` only. An upgrade without
  `--rollback` refuses it.
- **No credential on a non-terminal output.** An install that can create
  credentials shown once (a production OpenBao's root token and unseal key,
  the first uplink's bearer token) refuses when its output is not a terminal,
  unless `--secrets-file PATH` is given.

### Added

- `oberth install --secrets-file PATH` (#4). It writes those credentials to
  a new file with mode 0600 whatever the umask, as `OPENBAO_ROOT_TOKEN=`,
  `OPENBAO_UNSEAL_KEY=` and `OBERTH_UPLINK_TOKEN=` lines, each synced to disk
  as it is created. The output names only the path and the file's SHA-256.
  The file is reserved before the cluster is touched. An existing file, a
  symbolic link and any path inside a git worktree are refused. A run that
  created nothing removes it. The client-access notes then print a command
  that moves the token into the platform's secret store without showing it.
- **Non-interactive installs are complete** (#6, #10).
  - Without a terminal, the client-access offer takes its default (both
    clients): `~/.config/oberth/{ca.crt,env,mcp.json}` are written and, when
    Claude Code is installed, its CA trust and the Oberth plugin are set up
    as on a terminal. `--client-access none` declines.
  - The client files are written even when no upstream was given.
  - Onboarding runs from flags alone. The uplink identity defaults to
    `user@host`. Its key defaults to `~/.ssh/id_ed25519.pub`, else the first
    key pair in `~/.ssh`, else a new `~/.ssh/oberth_ed25519` generated on
    the machine.
  - `--expected-host-fingerprint SHA256:...` pins the first upstream's SSH
    host key, so a forge whose key Oberth does not ship is trusted without a
    prompt. The printed rerun command carries it.
  - An API server on 0.0.0.0 is reached as `localhost` in the printed
    commands.
- `--client-ssh-port` and `--client-https-port` (#6). They name the ports
  clients reach the server on, when those are not the Service's (a port
  forward, a container runtime that publishes the NodePorts elsewhere). The
  client files, the SSH config block, the push banner URL and every printed
  command use them.
- `oberth install --assist` turns on assisted continuation
  (`assist.enabled`, #11). On an installed server, use
  `oberth upgrade --set assist.enabled=true`. Both are now in
  docs/assisted-continuation.md.
- `oberth upgrade --backup-recipient CERT` (#11) encrypts the pre-upgrade
  backup to a certificate you manage. An upgrade without a terminal then
  needs no backup-key ceremony. The other path, `oberth backup keygen` and
  `oberth backup key --stored`, is now named in the refusal and the docs.
- `oberth --version`, and `oberth help [command...]`, which prints the
  command's `--help` (#3). Every command's flag help now starts with
  `Usage: oberth <command>`, never Go's `Usage of <name>:`.
- The install's next steps and the README name the first-promotion step
  (#15). The first uplink is not an admin, and a promotion needs a
  single-use `promote_grant` from an admin uplink. The person registers that
  uplink with `uplink add --admin`, with a key no agent holds, and issues the
  grant with `oberth mcp call --token-file ... promote_grant`. The install
  does not create an admin uplink: a token that can grant promotions must
  not be the agent's.
- **Plugin first** (#1521). The plugin's URL and token options are optional,
  so `/plugin install oberth@oberthci` works before any server exists. Its
  session-start note then offers `/oberth:install`, a new skill that drives
  `oberth install` non-interactively, or connecting to an existing server.
  The skill checks for kubectl and helm, installs the CLI into
  `~/.local/bin`, asks for the context and four answers, shows the command
  for an explicit "install", and keeps every credential in the secrets file.

### Fixed

- The upgrade plan no longer lists `secretstore.external` as a change nobody
  requested (#11). `helm get values --all` drops a chart default whose value
  is null, while the preview carries it. A null value and an absent key are
  now the same, as they are to Helm.
- docs/mcp-setup.md said `uplink add` prints three lines, including a TLS
  fingerprint (#9). It prints the token only. The docs now say so, and point
  to `oberth client pin` and the CA file for trust. Fetching the CA uses
  `umask 077`, because the CLI refuses a group-writable CA. The installer's
  own next steps no longer promise a TLS fingerprint either.
- The README documents installing the CLI without root
  (`OBERTH_INSTALL_DIR="$HOME/.local/bin"`, #2).

### Follow-ups outside this repository

- The website's install script still defaults to `/usr/local/bin` and
  verifies with `cosign verify-blob --insecure-ignore-tlog`. Releases since
  v0.17.96 carry a Rekor entry (.oberth/release.sh), so the script can verify
  with the transparency log and default to `~/.local/bin` when not root (#2).
- The website's navigation says "Source on request", but the repository is
  public and is where the production install is documented (#1).

# v0.21.4 release candidate

## Agent flows and metrics

Native replacements for client-side agent scripts (#1524) and a metrics-only
token for Prometheus scraping (#1534). No run status or label is added; the
outcomes are reason lines, `promote_status` fields and event data. One store
migration is added: `20261111132749-promotion-tags-c5ec022389eceac5d4f1120521ed20ef`
(`promotion_tags`).

### Breaking

- The Helm value `autoRetryInfrastructure` (boolean) and the server flag
  `--auto-retry-infrastructure` are replaced by `autoRetryInfrastructureBudget`
  and `--auto-retry-infrastructure-budget` (integer, default 2, 0 disables,
  at most 5). Values files that set the old key must set the new one.
- `/metrics` no longer suggests an admin token: `docs/metrics.md` and the
  chart's ServiceMonitor option now ask for a metrics-scoped token. An
  unscoped admin token is still accepted.
- An eviction for the step's own ephemeral-storage limit (`retry_hint` class
  `code`) is no longer retried automatically.

### Automatic infrastructure reruns

- A failed branch run whose `retry_hint` class is `infrastructure` (and that
  meets the existing eligibility rules) is rerun automatically up to the
  budget per lineage, default 2. Never for class `code`, tags, releases,
  promotions, plans or applies.
- The original's reason line links to the rerun (`infra error, retried as
  <id>`); the rerun's names the lineage origin and the cause. Every rerun is
  audited as `run.retry.auto` with its attempt number, budget and origin. A
  manual `run_rerun` inherits the lineage's spent budget.

### Tag after promotion

- `promote {..., tag_after: {name, message}}` pushes an annotated tag on the
  promotion result once the promotion passed and the upstream target equals
  the result, without force and with the publication retry schedule. The
  outcome (`pushed` or `failed` with a reason) is in `promote_status
  tag_after`, the `promotion.finished` event and the audit
  (`promotion.tag_after.*`). A malformed name, an empty message or an
  existing tag is refused before admission.

### Latest run per ref

- `oberth runs --ref-glob 'land/*' --latest` and MCP `run_list {ref_glob,
  latest: true}` list one row per matching repository and ref (its newest
  run) across every repository the caller's uplink scope reaches. `ref_glob`
  (also `GET /api/runs?ref_glob=`) uses the events' `refs_glob` syntax.

### Migration-sequence check

- Oberth's own CI (`generic-names` step) runs
  `.oberth/check-migration-sequence.py`: every store migration is listed in
  `.oberth/migration-sequence.txt`, a new one is numbered after main's latest,
  and IDs or timestamps never collide. `hack/new-migration.py` appends the
  new ID.

### Anonymised resource export

- `oberth run resources --anonymize` replaces repository, ref, burn and step
  names, commit SHAs and run IDs with keyed hashes drawn from a fresh
  per-export salt that is never printed.

### Metrics-only token scope

- `oberth uplink add --scope metrics` (or `oberth uplink scope --set metrics`
  on a non-admin uplink) mints a token that reads `GET /metrics` and nothing
  else: every other REST route and every MCP tool answer 403, and its SSH key
  never authenticates for git. The scope cannot be combined with another
  scope or with `--admin`; expiry and rotation follow the ordinary uplink
  rules.

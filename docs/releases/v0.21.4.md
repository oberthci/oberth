# v0.21.4 release candidate

This candidate builds on v0.21.3 and fixes what a fresh-install rehearsal
found: a non-interactive install of v0.21.3 on a new k3s cluster, run by an
AI agent with only kubectl and helm, followed by Claude Code with the Oberth
plugin (#1525, #1521). No run status or label is added. The agent-flow section describes the store migration.

## Install and CLI

### Breaking

- **Any reachable cluster is a target.** `oberth install`, `oberth setup`
  and `oberth upgrade` no longer classify clusters by API address. The
  "does not appear to be a local cluster" refusal is gone. It refused k3d
  clusters, whose API listens on 0.0.0.0, and spoke of a "dev secret store"
  when a production one was requested. With it go `oberth install --yes` and
  the setup wizard's second "Confirm remote install". The target is the
  kubeconfig context: setup lists the contexts of the selected kubeconfig
  (`--kubeconfig`, else `KUBECONFIG`, else `~/.kube/config`). `oberth install`
  and `oberth upgrade` (with `--rollback` too) take `--context` and refuse
  to pick one themselves when there are several, listing them. All name the
  context and its API server before acting (`Target: <context>
  (<server>)`, and the review summary). The review's Install confirmation is
  the only gate.
- `oberth upgrade --yes` applies to `--rollback` only. An upgrade without
  `--rollback` refuses it.
- **No credential on a non-terminal output.** An install that can create
  credentials shown once (a production OpenBao's root token and unseal key,
  the first uplink's bearer token) refuses when its output is not a terminal,
  unless `--secrets-file PATH` is given.

### Added

- `oberth install --secrets-file PATH` (#4). It writes those credentials to
  a new file with mode 0600 whatever the umask, as `OPENBAO_ROOT_TOKEN=`,
  `OPENBAO_UNSEAL_KEY=` and `OBERTH_UPLINK_TOKEN=` lines, each synced to disk
  as it is created. The output names only the path and the file's SHA-256.
  The file is reserved before the cluster is touched. An existing file, a
  symbolic link and any path inside a git worktree are refused. A run that
  created nothing removes it. `--dry-run` checks the path the same way and
  creates nothing. The client-access notes then print a command that moves
  the token into the platform's secret store without showing it or putting
  it in a process argument list. On macOS that command feeds `security -i`,
  because `security add-generic-password -w` takes a value only as an
  argument.
- **Non-interactive installs are complete** (#6, #10).
  - Without a terminal, the client-access offer takes its default (both
    clients): `~/.config/oberth/{ca.crt,env,mcp.json}` are written and, when
    Claude Code is installed, its CA trust and the Oberth plugin are set up
    as on a terminal. `--client-access none` declines.
  - The client files are written even when no upstream was given.
  - Client files that already exist with other content (another server,
    other ports, your own edits) are kept and nothing is written, unless
    `--replace-client-files` is given. A terminal's offer and the setup
    wizard's client-access step replace them as before.
  - Onboarding runs from flags alone. The uplink identity defaults to
    `user@host`. Its key defaults to `~/.ssh/id_ed25519.pub`, else to
    `~/.ssh/oberth_ed25519`, generated on the machine on the first run. No
    other key in `~/.ssh` is picked.
  - `--expected-host-fingerprint SHA256:...` pins the first upstream's SSH
    host key, so a forge whose key Oberth does not ship is trusted without a
    prompt. The printed rerun command carries it.
  - An API server on 0.0.0.0 is reached as `localhost` in the printed
    commands.
  - The `kubectl exec` commands the install prints for later (`upstream
    add`, `uplink add`) carry the install's `--context` and `--kubeconfig`,
    so they reach the cluster that was installed on.
- `--client-ssh-port` and `--client-https-port` (#6). They name the ports
  clients reach the server on, when those are not the Service's (a port
  forward, a container runtime that publishes the NodePorts elsewhere). The
  client files, the SSH config block, the push banner URL and every printed
  command use them.
- `oberth install --assist` turns on assisted continuation
  (`assist.enabled`, #11). On an installed server, use
  `oberth upgrade --set assist.enabled=true`. Both are now in
  docs/assisted-continuation.md.
- `oberth upgrade --backup-recipient CERT` (#11) encrypts the pre-upgrade
  backup to a certificate you manage. An upgrade without a terminal then
  needs no backup-key ceremony. The other path, `oberth backup keygen` and
  `oberth backup key --stored`, is now named in the refusal and the docs.
- `oberth --version`, and `oberth help [command...]`, which prints the
  command's `--help` (#3). Every command's flag help now starts with
  `Usage: oberth <command>`, never Go's `Usage of <name>:`.
- The install's next steps and the README name the first-promotion step
  (#15). The first uplink is not an admin, and a promotion needs a
  single-use `promote_grant` from an admin uplink. The person registers that
  uplink with `uplink add --admin`, with a key no agent holds, and issues the
  grant with `oberth mcp call --token-file ... promote_grant`. The install
  does not create an admin uplink: a token that can grant promotions must
  not be the agent's.
- **Plugin first** (#1521). The plugin's URL and token options are optional,
  so `/plugin install oberth@oberthci` works before any server exists. Its
  session-start note then offers `/oberth:install`, a new skill that drives
  `oberth install` non-interactively, or connecting to an existing server.
  The skill checks for kubectl and helm, installs the CLI into
  `~/.local/bin`, asks for the context and four answers, shows the command
  for an explicit "install", and keeps every credential in the secrets file.

### Fixed

- The upgrade plan no longer lists `secretstore.external` as a change nobody
  requested (#11). `helm get values --all` drops a chart default whose value
  is null, while the preview carries it. A null value and an absent key are
  now the same, as they are to Helm.
- docs/mcp-setup.md said `uplink add` prints three lines, including a TLS
  fingerprint (#9). It prints the token only. The docs now say so, and point
  to `oberth client pin` and the CA file for trust. Fetching the CA uses
  `umask 077`, because the CLI refuses a group-writable CA. The installer's
  own next steps no longer promise a TLS fingerprint either.
- The README documents installing the CLI without root
  (`OBERTH_INSTALL_DIR="$HOME/.local/bin"`, #2).

### Follow-ups outside this repository

- The website's install script still defaults to `/usr/local/bin` and
  verifies with `cosign verify-blob --insecure-ignore-tlog`. Releases since
  v0.17.96 carry a Rekor entry (.oberth/release.sh), so the script can verify
  with the transparency log and default to `~/.local/bin` when not root (#2).
- The website's navigation says "Source on request", but the repository is
  public and is where the production install is documented (#1).

## Upstreams and forges

- **Breaking:** `upstream add` and `upstream provide-key` no longer take
  `--upstream-key-secret` or `--known-hosts-secret`. The server only ever
  materialized the fixed `oberth-upstream-key` and `oberth-known-hosts`
  bundles, so another name failed with "unknown runtime identity bundle".
- **Multi-key forges.** The upstream authentication probe (used by
  `upstream add`, `upstream list --check` and server readiness) now offers
  only the host-key types pinned for the endpoint, as the Git transport
  already did. A stock OpenSSH forge with RSA, ECDSA and Ed25519 host keys
  pinned through `--expected-host-fingerprint` (which pins only the matching
  key) no longer fails with `knownhosts: key mismatch`.
- **`upstream add --repin`.** Rescans the forge's SSH host keys and replaces
  only this endpoint's pins in the known-hosts bundle, through the same
  audited write and the same trust rules as a first pin (published forge
  fingerprints, `--expected-host-fingerprint`, or an interactive `yes`). Pins
  for other endpoints are kept; a hashed or multi-host entry Oberth did not
  write is refused rather than edited. An identical existing registration is
  kept; another URL or key choice under the name is refused before anything
  is scanned or written. The interactive prompt lists the pins being replaced
  beside the scanned keys, and the write is audited as
  `upstream.identity.repin.oberth-known-hosts`. A host-key mismatch error now
  names `--repin`.
- **Organization path check.** `upstream add --check-repo <repo>` reads that
  existing repository through the new upstream (a ref advertisement, no
  objects) before registering it, and `upstream list --check` reads one
  registered repository per SSH upstream. A forge that serves no repository
  at the derived path is reported with the path tried and, for an absolute
  path, the home-relative `ssh://host/~/org` form that plain git-shell forges
  need. An in-protocol `ERR` answer counts as a refusal. The first clone's
  "does not appear to be a git repository" error now carries the same hint.
- **Empty upstreams.** A repository whose upstream default branch does not
  exist yet (an unborn HEAD, which stock OpenSSH forges never advertise) now
  keeps its recorded default branch, `main` for a new cache, even after
  Oberth has synced other branches there. The first promotion or
  default-branch publication creates it. Before, every refresh failed with
  "upstream did not advertise a symbolic default branch", the cache was
  served stale, and runs failed as infrastructure errors and were
  auto-retried. Release tags stay refused until the default branch exists.
  This applies only while the cache has never seen a default branch
  upstream: one that existed and was deleted beside other refs is refused as
  "upstream default branch unknown" rather than read as a new repository, so
  its policy never lapses.
- **Default branch errors are configuration.** An upstream whose HEAD
  resolves without naming its branch still refuses, now as "upstream default
  branch unknown": the run reason says "upstream configuration error", the
  retry hint is `upstream_configuration` (class `code`), and the run is not
  auto-retried.
- **Stale notices say why.** "serving cached repository" now names the
  cause (for example the unknown default branch) instead of always
  "upstream unavailable", and a push's park-policy fallback reports the
  failed refresh's cause instead of "recent upstream policy snapshot
  unavailable".
- **Server SSH host key out of band.** `system_status` and `/api/status`
  carry `ssh_host_key` (the server's public host key) and
  `ssh_host_key_fingerprint`; `oberth status` prints the fingerprint. Both
  arrive over the CA-verified API, so Git clients can pin the push endpoint
  without trusting it on first use.
- **Assisted holds on any image.** The server helper that `run_hold_patch`
  uses is now mounted on every hold-eligible step. It was dropped from steps
  without an explicit memory limit of at least 256Mi (most stock-image
  steps), which made them `patch_capable: false`.
  [Assisted continuation](../assisted-continuation.md) now says exactly when
  a step is patch-capable.

## Agent flows and metrics

Native replacements for client-side agent scripts (#1524) and a metrics-only
token for Prometheus scraping (#1534). No run status or label is added; the
outcomes are reason lines, `promote_status` fields and event data. One store
migration is added: `20261111132749-promotion-tags-c5ec022389eceac5d4f1120521ed20ef`
(`promotion_tags`).

### Breaking

- The Helm value `autoRetryInfrastructure` (boolean) and the server flag
  `--auto-retry-infrastructure` are replaced by `autoRetryInfrastructureBudget`
  and `--auto-retry-infrastructure-budget` (integer, default 2, 0 disables,
  at most 5). Values files that set the old key must set the new one.
- `/metrics` no longer suggests an admin token: `docs/metrics.md` and the
  chart's ServiceMonitor option now ask for a metrics-scoped token. An
  unscoped admin token is still accepted.
- An eviction for the step's own ephemeral-storage limit (`retry_hint` class
  `code`) is no longer retried automatically.

### Automatic infrastructure reruns

- A failed branch run whose `retry_hint` class is `infrastructure` (and that
  meets the existing eligibility rules) is rerun automatically up to the
  budget per lineage, default 2. Never for class `code`, tags, releases,
  promotions, plans or applies.
- The original's reason line links to the rerun (`infra error, retried as
  <id>`); the rerun's names the lineage origin and the cause. Every rerun is
  audited as `run.retry.auto` with its attempt number, budget and origin. A
  manual `run_rerun` inherits the lineage's spent budget.

### Tag after promotion

- `promote {..., tag_after: {name, message}}` pushes an annotated tag on the
  promotion result once the promotion passed and the upstream target equals
  the result, without force and with the publication retry schedule. The
  outcome (`pushed` or `failed` with a reason) is in `promote_status
  tag_after`, the `promotion.finished` event and the audit
  (`promotion.tag_after.*`). A malformed name, an empty message or an
  existing tag is refused before admission. Admin uplinks only; the tag is
  not a release and starts no tag run.

### Latest run per ref

- `oberth runs --ref-glob 'land/*' --latest` and MCP `run_list {ref_glob,
  latest: true}` list one row per matching repository and ref (its newest
  run) across every repository the caller's uplink scope reaches. `ref_glob`
  (also `GET /api/runs?ref_glob=`) uses the events' `refs_glob` syntax.

### Migration-sequence check

- Oberth's own CI (`generic-names` step) runs
  `.oberth/check-migration-sequence.py`: every store migration is listed in
  `.oberth/migration-sequence.txt`, a new one is numbered after main's latest,
  and IDs or timestamps never collide. `hack/new-migration.py` appends the
  new ID.

### Anonymised resource export

- `oberth run resources --anonymize` replaces repository, ref, burn and step
  names, commit SHAs and run IDs with keyed hashes drawn from a fresh
  per-export salt that is never printed.

### Metrics-only token scope

- `oberth uplink add --scope metrics` (or `oberth uplink scope --set metrics`
  on a non-admin uplink) mints a token that reads `GET /metrics` and nothing
  else: every other REST route and every MCP tool answer 403, and its SSH key
  never authenticates for git. The scope cannot be combined with another
  scope or with `--admin`; expiry and rotation follow the ordinary uplink
  rules. `metrics` is now a reserved upstream name.

### Review follow-ups

- Admin-only `tag_after` refuses release-version names, including prereleases.
- Automatic retries preserve assist, wait five seconds before dispatch, and use the current audit receipt format only.
- CI compares migrations with the fetched default branch, including before the sequence file first exists there.
- Resource exports anonymize refs named `any` and `default` too.

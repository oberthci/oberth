# v0.21.3 release candidate

This candidate builds on v0.21.2. Claude Code now connects to Oberth through
one plugin: it asks for the server URL, the uplink token and a CA pin, trusts
the CA only when it matches the pin, and follows one `events_wait` loop
instead of polling (#1521, first phase). `oberth client setup` is reduced to
the same two steps. No run status, label, layout or migration is added.

## Breaking

- `oberth client setup` no longer registers a user-scope MCP server
  (`claude mcp add-json oberth --scope user`). It trusts the CA and installs
  the plugin; the plugin's entry is the only one. `--token-command` and
  `--ca-trust system` are gone, and the command no longer runs
  `claude mcp get`.
- The plugin has no `headersHelper` and reads neither `OBERTH_MCP_URL`,
  `OBERTH_TOKEN_COMMAND` nor `~/.config/oberth/token`: its URL and token are
  its own options, entered once in Claude Code. `scripts/auth-header` is
  removed.
- The plugin marketplace is named `oberthci`: install with
  `claude plugin install oberth@oberthci`.
- `oberth client setup` stores the CA under Claude Code's own directory
  (`~/.claude/oberth/ca.crt`) and points `env.NODE_EXTRA_CA_CERTS` there. A
  setting that names another file holding the CA is kept as it is.

## Claude Code plugin

- **Options instead of files.** The plugin declares three options that
  Claude Code asks for when it is enabled: the MCP URL, the uplink token
  (sensitive: masked, and kept in Claude Code's credential store, never in
  `settings.json`) and the CA SHA-256 pin. Its MCP entry uses them in a plain
  `url` and `Authorization` header, with `"timeout": 630000`.
- **`/oberth:connect`.** Reads the certificates the server presents without
  trusting them and accepts the CA only when its SHA-256 equals the pin;
  there is no trust on first use, and a mismatch changes nothing. The pinned
  certificate must be a CA and must have issued the server's certificate;
  only the pinned CA anchors that check. A CA without critical name
  constraints is stored with a one-line warning that Claude Code will trust
  it for every host; `oberth client setup` prints the same line. The
  CA is stored as `~/.claude/oberth/ca.crt` and merged into
  `env.NODE_EXTRA_CA_CERTS` in `~/.claude/settings.json` in place: every
  other setting and the file's formatting are kept, and a bundle the variable
  already names is kept (when it holds the CA) or copied with the CA added.
  Settings that are not valid JSON are refused and left as they are. The
  operating system's trust store is never touched. Claude Code needs one
  restart afterwards. The command needs `sh`, `awk` and `openssl`; the URL
  may hold only letters, digits and `. _ ~ : / % @ [ ] -`.
- **Session hint.** A SessionStart hook tells Claude to offer
  `/oberth:connect` while a pin is configured and the CA is not trusted, and
  prints nothing once it is.
- **The agent loop is one `events_wait`.** The `oberth-agent-loop` skill and
  the server's MCP instructions make
  `events_wait {kinds:[run.held,run.finished], own:true, after_id, timeout_s:600}`
  the default while runs are in flight: Claude Code runs the long call in the
  background, its result wakes the session, and the next call continues from
  `next_after_id`. Event ids make a pushed copy of the same event harmless,
  so the per-session channel flag is optional.

## Server and CLI

- The server presents its CA after its leaf in the TLS handshake, so a
  client that pins the CA can read it before trusting anything. Verifying
  clients are unaffected. A renewed leaf keeps presenting it.
- `oberth client pin` prints the SHA-256 pin of the deployment's CA (64 hex
  digits) from `--ca-file`, `OBERTH_CA_CERT` or `~/.config/oberth/ca.crt`,
  without contacting the server.
- `oberth client setup` installs the plugin when it is missing
  (`--marketplace` names another source), sets its URL and CA pin, and hands
  a token this machine already holds to Claude Code's credential store on
  standard input; the token reaches no argument list, output or file of
  Oberth's. `oberth install` does the same for its own machine, without the
  token: the plugin asks for it.

## Verified with Claude Code 2.1.322

- `${user_config.*}` is substituted in a plugin MCP entry's `url` and
  `headers`, including a sensitive option: a request to the configured server
  carried the `Authorization` header.
- `claude plugin install --marketplace` and
  `claude plugin configure --values-stdin` set options without a prompt;
  sensitive values go to the credential store, the others to `pluginConfigs`
  in `settings.json`.
- A CA stored by `/oberth:connect` and named in `env.NODE_EXTRA_CA_CERTS` of
  `settings.json` is trusted by the next Claude Code process for the plugin's
  HTTPS MCP server.

## Upgrading

1. Upgrade the server first, so it presents its CA.
2. On each machine that runs Claude Code, run `oberth client setup` once, or
   install the plugin (`claude plugin install oberth@oberthci`), enter the
   URL, the token and the pin `oberth client pin` prints, and run
   `/oberth:connect`. Restart Claude Code.

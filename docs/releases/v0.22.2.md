# v0.22.2

## Granted resource metadata

Resource admission checks annotation and label maps under every parent field,
including nested templates and list entries. A custom controller field no longer
bypasses the Pod metadata rules merely because its parent has another name.

## Block PVC devices

Per-Workflow block-mode PVCs remain supported through Kubernetes
`volumeDevices`. The native scheduling documentation now states this explicitly;
host devices and existing PVC references remain outside this admission.

## Pod metadata route coverage

The pinned Argo type graph now requires an explicit classification for every
ObjectMeta or metadata-like field, including labels, annotations and patches.
Pod writer classifications point to admission cases in the route table. A new
field cannot become covered just by updating the golden type inventory.

## Held Pod helper trust

The assist documentation states that helper responses are author-controlled,
including when an image symlink bypasses a literal path reservation. A forged
successful helper acknowledgement cannot remove the assisted verdict or make
that run eligible for upstream publication.

## Server certificate IP constraints

The existing CA issuance code already constrains IPv4 and IPv6 SANs to exact
/32 and /128 ranges. New regressions inspect the issued certificate and verify
matching leaves, with the DNS-only path retained. Existing CAs are unchanged.

## Installer plan receipt

The NetworkPolicy plan receipt is documented as a convenience cache writable by
the installer user. It saves a repeated measurement, provides no security
boundary against that user, and leaves every other install preflight in place.

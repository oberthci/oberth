# v0.22.4

## Security

Workflow admission now refuses `spec.templateDefaults.dag` and
`spec.templateDefaults.steps`. Argo could add their inline containers after
Oberth applied source and credential protections, allowing those containers to
mount server-owned volumes without the protections. Declare tasks and steps in
concrete templates instead. Container, script, and metadata defaults remain
subject to their existing admission and protection rules.

Nonempty `spec.templateDefaults.sidecars` and `.initContainers` are also
refused: Argo could add these helpers after container security hardening.
Default `volumeDevices`, like default `volumeMounts`, are refused so they
cannot expose server-owned volumes after mount protection. Declare helpers,
mounts, and devices on each concrete Pod template instead.

## Trivy cache admission

Oberth no longer refuses unordered Trivy steps that share a cache. Order these
steps with native Argo `depends`, or use a synchronization mutex.

## Secret delivery

The envconsul credential chain is removed. Use `oberth secretstore exec`;
other commands receive no secret-store login token. HCL remains an indirect
dependency of the Vault API client.

## Workflow recovery

Recovery no longer unwraps the retired step observer command or replays helper
storage policies V1-V3 or the unversioned policy. Only the current V4 helper
policy is supported. Drain old in-flight Workflows before upgrading: removed
execution formats are refused during recovery, with no compatibility replay.
The retired execution-annotation refusal list is removed. The executor-token
waiter protections from v0.22.3 are retained; that release already removed the
old waiter.

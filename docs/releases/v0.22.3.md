# v0.22.3

## Security

### Step outputs could return the executor token (#1564)

Argo's wait container reads `outputs.parameters[].valueFrom.path` and a
script's `outputs.result` with a plain file read inside its own filesystem,
and the read follows symlinks. A step could create a symlink to
`/var/run/secrets/kubernetes.io/serviceaccount/token` and get the wait
container's executor token back as an output. This was confirmed against Argo
v4.0.8 with Oberth's real Pod shape through five routes: a parameter path on
`/work/artifacts` (absolute and relative symlink), on `/tmp`, a path outside
any volume through a symlink planted under `/var/run/argo/outputs/parameters`,
and the script result through a symlink in place of
`/var/run/argo/ctr/main/stdout`. The executor token can create and patch
WorkflowTaskResults in the pipeline namespace while the run's identity Pod
exists. Refusing `valueFrom.path` would not have closed the last two routes.

The in-cluster default token path is now empty in executor containers.
Oberth delivers the token under a random 128-bit directory name, created per
delivery in the executor's memory volume, and writes a kubeconfig that names
it. Argo's init and wait containers, and the main container of resource and
data templates, read that kubeconfig through `KUBECONFIG`. The protection is
the unguessable name: it never appears in a Kubernetes object, a symlink is a
fixed path chosen before wait reads it, and a step cannot see wait's
filesystem. No Workflow field is refused or rewritten.

The directory is mode 0111, but that does not stop a wait container running
as root with the runtime's default capabilities, which is Argo's default
without the nonroot profile. Nothing lists it today: output artifacts, data
templates and `archiveLocation` are refused at admission. Future artifact
work must not let a directory output artifact archive the executor volume or
any parent of it, because a recursive archive would include the token.

The hostile Workflow now runs as a live regression
(`TestLiveOutputPathsCannotReadTheExecutorToken`). Argo's controller proofs
were recaptured with the authenticated v4.0.8 controller.

Pods created by an earlier server still wait for the old token path. The new
server refuses to deliver to them, so a run that was in progress across the
upgrade fails with an executor identity error and must be rerun.

# v0.21.7

## #1537 item 9(c) — Tag-after CI admission

- A verified `tag_after` publication now queues ordinary tag CI through the
  shared receive/admission path. Durable receive IDs prevent another run after
  an admission/settlement retry or restart; the reason names the queued run.
- Non-version tags use `build.yaml` with tag identity and CI authority. Release
  versions and explicit administrator release routes retain release admission;
  `tag_after` refuses both. Normal tag CI never acquires release authority from
  its tag trigger, including on adoption and rerun.
- Tag objects and tested commits stay separate. Existing default-branch ancestry,
  immutability, audit and publication gates continue to apply.

## #1536 — verify encrypted install recovery with age

- Add an integration regression using real `age` and `age-keygen` when available. It checks that an interrupted install saves an encrypted, owner-only recovery snapshot, that recovery and unseal decrypt it through an inherited identity descriptor, and that failed unseal, incorrect identities and truncated ciphertext do not disclose credentials.

- Secret-store test fixtures also withhold command payloads and stdin on unexpected-command failures.

## #1538 — Node reboot failures and safe tag replay

- Register the node-boot migration in the append-only sequence and retain node boot IDs for owned running step Pods across server resumes. A changed boot ID makes ambiguous kubelet terminations infrastructure failures; branch retries use the existing bounded budget.
- Reboot reason lines name the node and the observed restart window. Missing evidence, ordinary command failures and OOMs keep their existing classification.
- Unknown terminations and exit 255 settle without an assisted hold. Exit 255 reported as a command error additionally requires a resumed step with readable empty output since resume before reboot attribution.
- Skipped publication nodes no longer emit synthetic running progress. Their required timestamps and progress markers do not count as publication execution; earlier starts and publication attempts still require force.
- The chart grants the server only `get` on nodes in a separate role named for its release and namespace, so installations in different namespaces do not collide. Execution targets need the same read permission; no node proxy or kubelet access is used.

## #1521 — Single-use certificate invitations

- `oberth uplink invite` creates an expiring invitation in a new private file, with only the credential digest sent to the admin MCP tool.
- The dedicated enrollment MCP endpoint accepts a local CSR and SSH public key, atomically consumes the invitation and registers a certificate-only uplink. No bearer token is issued.
- `/oberth:connect` redeems the private file with CA pin and hostname verification before credential transmission, keeps private keys local, and configures Claude Code for mutual TLS.

- Invitation review: reject unknown credentials before taking the database writer, transmit only canonical public inputs, require DNS server URLs, and preserve the exact credential binding during atomic enrollment. The unshipped invite migration follows the leftovers migrations.

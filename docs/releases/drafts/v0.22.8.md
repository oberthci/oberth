# DRAFT: v0.22.8

DRAFT throughout: these are slice-report expectations, not a promoted release
or proof of the assembled train. v0.22.7 remains the documentation base.

## Operators — DRAFT

Before upgrade, take a backup and review native cleanup defaults. The reported
installer fills an absent
`controller.workflowDefaults.spec.ttlStrategy.secondsAfterCompletion` with 3600
before deploying the server. Explicit null, empty, zero and custom settings are
preserved. External controllers and server-only chart upgrades must establish
their cleanup defaults first. Kubernetes 1.33 and the qualified Argo v4.0.8
configuration remain the reference requirements; no namespace Pod Security
label change is planned here.

Shared Workflow and Pod watches replace per-run polling. Cluster observation
outages keep runs unresolved with a timestamped status-unknown reason, then
catch up to a live-confirmed Argo verdict. Restart adoption processes completed
Workflows for available logs and identity retirement. Accepted submissions start
immediately; create failures need an explicit new attempt. Argo controls
parallelism. Promotions are planned immediately and re-prepare against a moved
target. Grants move to the database as their only authority; the ConfigMap
mirror disappears.

Container logs use live Kubernetes streams and one bounded stored copy per
container. Missing or partial copies get a reason. Aggressive PodGC can remove
logs before capture; a TTL that deletes the Workflow too soon can also lose its
verdict. After upgrade, check a running and completed run, stored logs, native
step rows, outage recovery and the effective cleanup default.

The reported cleanup removes unreachable execution-target ownership code and
old chart archives. Restore across chart generations still requires
`oberth upgrade` first; no restore compatibility promise is added.

## Repository authors — DRAFT

Authored `ttlStrategy` and `podGC` pass through unchanged. Use a cleanup interval
that leaves time to observe completion and capture logs. Step history comes
from Argo node IDs, including retries, loops and duplicate display names;
marker-looking log lines become ordinary text. Existing history stays readable.

Overlapping schedule occurrences have independent Workflows; cron coalescing
and the manual busy guard disappear. `force` only overrides a paused entry.
The native CronWorkflow cutover belongs to the v0.23.1 draft.

The reported client plugin adds recent-run tables and live run watching without
a server scheduling mechanism. See the [migration guide](../../migrating-to-native-workflows.md)
for cleanup YAML and operational checks. Every behavior in this draft requires
final train integration and qualification.

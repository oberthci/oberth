# DRAFT: v0.23.0

DRAFT throughout: source activation, cache integration, native template sharing
and release qualification are pending. Slice reports and separate slice code
do not establish the behavior of an assembled release.

## Operators — DRAFT

Before upgrade, stop submissions, drain all pre-upgrade Workflows including
exit handlers, and take a backup. Since the v0.22.8 draft, a version-changing
upgrade waits for idle by default with a visible countdown and a bounded timeout
that refuses rather than proceeding. `--no-wait-idle` skips it; the wait does
not freeze admission. Prepare consuming repositories' YAML for deployment
after the new server is active.

The source plugin must be registered with the Argo controller, using the
release's plugin image and public TLS trust. The reported source listener uses
port 8445; review its Service, NetworkPolicy and TokenReview permissions. The
native executor environment needs the fixed kubeconfig path and zero progress
ticks. Managed reconciliation fills absent settings with consent, preserving
unrelated values and refusing conflicts. External controllers need the same
live settings. With `--skip-argo-workflows`, the installer verifies and never
takes over a controller ConfigMap; takeover is limited to the Argo release
installed by Oberth. Do not deploy source authorization components separately.

Reported source delivery replaces source claims and seed Pods with private
Pod-local inputs. Files plus history share a 512 MiB cap, including sanitized
Git metadata; pins retain separate projection limits. A single active export
bounds disk use during export; busy readers retry. Confirm source loads,
retry, restart and cancellation in the assembled train before release.

HostPath caches and the root preparation initializer disappear. Provision
existing PVCs in the pipeline namespace, then have an unscoped administrator
grant each literal claim name to one repository and one tier. A revoked claim
cannot be reassigned to another repository/tier. CI steps holding secret grants
cannot mount any granted claim, even read-only. One claim means one repository
and one tier. Release claims need release-tier
grants, including in release preflight.

The reported installer raises pipeline Pod Security enforcement to baseline and
server enforcement to restricted after successful rollout, preserving stricter
operator policy. Rollback restores previous labels before old Pods restart.
Dry-run and upgrade review must show these changes. Retired stored cache roots,
`argo.sourceStorageClass` and `retention.artifacts.limitBytes` are removed by
upgrade; delete those keys from operator override files too.

After upgrade, apply the authored YAML and verify source loading, granted
secret access, cache isolation and a real assist hold under baseline. Once no
old Workflow or exit handler remains, review and delete leftover claims and
seed Pods labelled `oberth.ci/component=source` in the pipeline namespace.
Workflow-owned resources otherwise follow TTL cleanup. Node cache directories
are the node administrator's responsibility.

Historical artifacts retain authenticated reads, retention and purge. New runs
produce no durable collected artifacts. History backups do not acquire the
old artifact/log bytes; preserve them separately when needed for restore.

## Repository authors — DRAFT

Declare the exact native `oberth` main/pin input on every Pod that needs source;
remove `sources:` and its annotation. Inputs are private per Pod. Declare
Pod-local scratch and publish required files in your own steps. Output artifacts,
artifact GC and archived logs remain refused without an output backend; output
parameters/results remain available subject to credential guards.

Declare secret access in the granted inline step itself: client image,
exact-audience projected token, read-only token mount at
`/var/run/secrets/secretstore`, public CA and optional memory scratch. The
token file is `token`. Only `oberth-secretstore-address` is a store parameter;
there is no role parameter. The optional helper derives the role from the
projected identity. Other clients can read exactly `spec.serviceAccountName`
through a fieldRef. Every container in that step shares its trust. Argo's
trusted helpers retain native mirrors.

Name PVCs, mounts and tool env explicitly. Remove obsolete workspace annotations
and injected helper paths. Assist remains opt-in with its own carrier.

The owner-decided sharing target is namespaced `templateRef` to existing
WorkflowTemplates installed by a shared pipeline repository. Granted steps stay
inline in consuming repositories. Cluster scope and `workflowTemplateRef` remain
refused. Admission, template identity policy and exact new refusal wording
still need implementation evidence; the inspected slices currently refuse
all templateRef forms. Do not migrate sharing until that prerequisite lands.

The [migration guide](../../migrating-to-native-workflows.md) contains the YAML
recipes, newly refused shapes, exact available messages and outstanding proof.

# DRAFT: v0.23.1

DRAFT throughout: the native schedule cutover is not established by the
documentation base or by slice readiness alone.

## Operators — DRAFT

Before upgrade, back up the installation and record current schedule pause
intent. Source-in must be active before native schedules can be enabled. Check
the server's CronWorkflow permissions and the controller's ability to create
child Workflows in the pipeline namespace.

The owner-decided target is one native Argo CronWorkflow per schedule entry,
event-driven synchronization on relevant pushes and authority changes, and
child adoption as ordinary runs. Stored v0.22.x pauses must be imported once as
suspended CronWorkflows. Revocations suspend affected schedules synchronously;
failed synchronization retries on events or startup rather than a new polling
loop. Removing an entry uses orphan deletion so running children survive.

After upgrade, verify imported pauses, trigger/pause/resume behavior, grant
revocation, source authorization and child adoption. Do not tag this release
until native activation is on and a schedule has fired and been adopted on a
real Argo controller. Qualification includes missed runs, Forbid overlap and
removing an entry with a running child. Reports still identify activation and
pause import as pending; those claims are release requirements, not proven
implementation.

## Repository authors — DRAFT

Keep `.oberth/schedule.yaml` as the schedule declaration. Argo owns execution,
concurrency and missed-run handling through native CronWorkflows; Oberth's
local cron engine and cursor disappear. `schedule_pause` and `schedule_trigger`
become thin native wrappers.

The final owner decision requires authored `concurrencyPolicy` to pass through,
using Argo's default Allow when absent; there is no hard-coded Forbid or manual
busy guard. The inspected CRON-A object constructor still
hard-codes Forbid, and the authored field location is not established. Do not
add an invented schedule key. The [migration guide](../../migrating-to-native-workflows.md)
shows the native target shape and distinguishes it from repository input.

Minimum interval and entry-count admission checks remain. Do not assume the
old once-after-downtime/coalescing semantics survive the cutover; verify the
rendered native deadline, timezone and history settings before activation.

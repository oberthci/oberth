# v0.22.1

## Source preparation after a restart

A retried source copy can reuse a seed Pod left by the previous server. If
restart cleanup removes that reused Pod, Oberth recreates it once and resumes
preparation. A Pod created by the current attempt that disappears still fails
the run; repeated disappearance does not cause a recreation loop.


Pending source-seed reason lines survive a server restart. Read-only observation
uses the run's canonical Workflow name to find its deterministic seed Pod and
checks the server seed shape before returning curated Kubernetes reasons.
It does not adopt or repair objects or expose raw controller messages.


An unapproved secret-path refusal and its retry hint explain both remedies:
correct the Workflow path, or ask an operator to approve access and rerun.
Other document refusals continue to request a YAML correction.


Malformed fragment references and resolved fragment-template rules are document
refusals, preserving their rule text and YAML-fix retry hint. Missing/corrupted
server-supplied fragment bindings, loader configuration and transport failures
remain infrastructure errors.

Workflow-object annotations remain on the Workflow: root metadata annotations
and workflowMetadata annotations are not copied to Pods by the pinned Argo
controller. The regression runs the real controller Pod builder against the
Workflow posted by Oberth; author Pod annotations remain refused.

Run-list execution observations are cached for two seconds, avoiding repeated
Workflow and Pod reads on each poll. The bounded refresh queue still coalesces
concurrent readers, preserves observation age and separates attempts and scopes.

A retained queued run whose repository is archived now says "repository archived"
on lists, detail and status, with an operator-unarchive remedy. Reads do not start
the run or change its durable status.

Repository verification no longer tries to kill a process group when the Git
probe has exited and no living descendants remain. Confinement that refuses
group signals therefore no longer hides a successful forge result or its actual
error. Living descendants still require successful cleanup before returning.

MCP registry counts in README, setup documentation, the agent contract and plugin
skills are generated from the registered tools. The skills tell agents to report
the inventory their client actually exposes, distinguishing the Oberth server's
visible tools from a combined count across servers.

Pending Pod reasons include Kubernetes scheduler phrases for extended resources
and affinity constraints. Observations remain read-only and expose bounded reason
phrases rather than unrelated status text.

A failed semaphore initialization now asks the operator to create or correct
`oberth-sync-limits` and its key, or the author to fix the Workflow reference.
It no longer suggests that an infrastructure retry alone repairs the limit.
This includes Argo’s ConfigMap-form lock errors for missing maps and keys.

The native scheduling inventory names the executor-token waiter
`oberth-executor-token`; a regression compares its helper-name table with
containers emitted by the Workflow compiler.

Run detail, lists and status use the same wording for an Argo controller
parallelism wait: "waiting for an Argo workflow slot (controller parallelism)".

Expired execution observations are withdrawn from the primary reason line
after two seconds, even while refresh is queued or unavailable. A slow refresh
backlog cannot keep asserting an old suspension or scheduling reason.

Git cancellation under a policy refusing process-group signals falls back to
individual signals through pidfds after checking command-group membership.
The command leader and descendants are joined before returning the cancellation
or deadline error; unrelated processes are neither signaled nor reaped.

## Installer planning and candidate versions

A successful NetworkPolicy measurement from `install --plan` can be reused
once by an install for five minutes. A private receipt binds the verified
cluster and pipeline namespace identity, labels, nodes and probe configuration.
Other preflight checks still run. Missing, expired, failed or mismatched proof
runs the complete live measurement; fresh installs retain the enforcement gate.

Installing a source chart with a versioned candidate binary stamps a private
chart copy with the candidate version (or explicit `--chart-version`). Helm
release metadata and notes use that version; the source checkout is unchanged.

## IP client endpoints (#1559)

Clients may connect by IPv4 or IPv6 when the server certificate carries the
exact IP SAN. Setup offers detected node addresses and user-supplied names or
IPs alongside localhost; the chosen address is included in certificate SANs,
plan, Review and the install summary. The port probe preserves IP choices
without requiring a DNS alias. DNS and localhost remain supported.

Plugin connect verifies the endpoint identity as well as its pinned CA before
saving trust. On macOS it can use Homebrew OpenSSL when system LibreSSL lacks
the required identity checks; otherwise it stops with a dependency remedy. Invitation clients also accept IP URLs with strict pin, chain
and IP SAN checks. MCP settings and Git SSH bindings preserve IPv4/IPv6 hosts.
CA generation and existing constraints are unchanged.

NodePort advice now explains that reachability depends on the network between
client and node. NAT-isolated guests need port-forwarding or a name/IP routable
from the client; an install alone does not create that route.

Client-port advice distinguishes DNS mismatches from individual TCP results.
A port that did not answer does not establish a missing route. A DNS-only
mismatch no longer invents a NodePort failure or LoadBalancer remedy.

## NetworkPolicy measurement hardening

- Every measurement exec explicitly selects the probe container, including
  held responses, marker checks and release. A sidecar default-container
  annotation cannot redirect it.
- Scratch namespaces always enforce restricted Pod Security (also audit/warn,
  version latest). They retain only generated ownership and Pod Security labels;
  pipeline labels, including injection labels, are omitted. The owned policy
  needs only the probe Pod label. Namespace-name/label-specific exemptions and
  installed policy rules are explicitly outside this measurement's scope.
- Pods are tracked by the UIDs returned at creation. Readiness, exec and traffic
  stage completion reject same-name replacements, even with identical labels
  and IPs. Kubectl exec has no atomic UID precondition; before/after UID checks
  prevent a detected replacement's result from being credited.
- Each round removes only the NetworkPolicy UID returned by that round's
  create response. A replacement under the same name fails the API delete
  precondition and leaves the measurement unverified.

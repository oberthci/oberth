# v0.22.1

- Workflows stopped with native `argo stop` or `argo terminate` are recorded as
  interrupted/cancelled with “stopped by operator” and Argo's original message.
  They retain observed step evidence and do not receive an infrastructure retry
  hint. Ordinary execution failures and server interruptions keep their existing
  classifications.

- Install and `install --verify --json` use the same HTTPS check code,
  `client_bootstrap_endpoint`, and the same routing/recovery remedy. SSH retains
  `ssh_reachable` with that shared remedy, including both forwarding ports.

- Historical workflow-capability recovery requires the original Workflow UID
  as well as repository, run, name and tested SHA. A forward migration discards
  existing UID-less receipts without backfilling from live objects. Finish or
  cancel old device-grant Workflows with the old owner before upgrade if they
  depend on those receipts; refused Workflows remain for operator inspection.
  Current grants, run records and audit history stay intact.

- Authored mounts and block devices cannot shadow `/run/oberth`, including the
  held-Pod assist helper, its parents and nested paths. The conventional
  `/var/run/oberth` alias and runtime-templated paths are also refused. Existing
  held Pods with shadowing mounts are inspect-only for patching and use the
  release fallback.

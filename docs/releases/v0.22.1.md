# v0.22.1

## Source preparation after a restart

A retried source copy can reuse a seed Pod left by the previous server. If
restart cleanup removes that reused Pod, Oberth recreates it once and resumes
preparation. A Pod created by the current attempt that disappears still fails
the run; repeated disappearance does not cause a recreation loop.


Pending source-seed reason lines survive a server restart. Read-only observation
uses the run's canonical Workflow name to find its deterministic seed Pod and
checks the server seed shape before returning curated Kubernetes reasons.
It does not adopt or repair objects or expose raw controller messages.


An unapproved secret-path refusal and its retry hint explain both remedies:
correct the Workflow path, or ask an operator to approve access and rerun.
Other document refusals continue to request a YAML correction.


Malformed fragment references and resolved fragment-template rules are document
refusals, preserving their rule text and YAML-fix retry hint. Missing/corrupted
server-supplied fragment bindings, loader configuration and transport failures
remain infrastructure errors.

Workflow-object annotations remain on the Workflow: root metadata annotations
and workflowMetadata annotations are not copied to Pods by the pinned Argo
controller. The regression runs the real controller Pod builder against the
Workflow posted by Oberth; author Pod annotations remain refused.

Run-list execution observations are cached for two seconds, avoiding repeated
Workflow and Pod reads on each poll. The bounded refresh queue still coalesces
concurrent readers, preserves observation age and separates attempts and scopes.

A retained queued run whose repository is archived now says "repository archived"
on lists, detail and status, with an operator-unarchive remedy. Reads do not start
the run or change its durable status.

# v0.22.1

## IP client endpoints (#1559)

Clients may connect by IPv4 or IPv6 when the server certificate carries the
exact IP SAN. Setup offers detected node addresses and user-supplied names or
IPs alongside localhost; the chosen address is included in certificate SANs,
plan, Review and the install summary. The port probe preserves IP choices
without requiring a DNS alias. DNS and localhost remain supported.

Plugin connect verifies the endpoint identity as well as its pinned CA before
saving trust. On macOS it can use Homebrew OpenSSL when system LibreSSL lacks
the required identity checks; otherwise it stops with a dependency remedy. Invitation clients also accept IP URLs with strict pin, chain
and IP SAN checks. MCP settings and Git SSH bindings preserve IPv4/IPv6 hosts.
CA generation and existing constraints are unchanged.

NodePort advice now explains that reachability depends on the network between
client and node. NAT-isolated guests need port-forwarding or a name/IP routable
from the client; an install alone does not create that route.

Client-port advice distinguishes DNS mismatches from individual TCP results.
A port that did not answer does not establish a missing route. A DNS-only
mismatch no longer invents a NodePort failure or LoadBalancer remedy.

## NetworkPolicy measurement hardening

- Every measurement exec explicitly selects the probe container, including
  held responses, marker checks and release. A sidecar default-container
  annotation cannot redirect it.
- Scratch namespaces always enforce restricted Pod Security (also audit/warn,
  version latest). They retain only generated ownership and Pod Security labels;
  pipeline labels, including injection labels, are omitted. The owned policy
  needs only the probe Pod label. Namespace-name/label-specific exemptions and
  installed policy rules are explicitly outside this measurement's scope.
- Pods are tracked by the UIDs returned at creation. Readiness, exec and traffic
  stage completion reject same-name replacements, even with identical labels
  and IPs. Kubectl exec has no atomic UID precondition; before/after UID checks
  prevent a detected replacement's result from being credited.
- Each round removes only the NetworkPolicy UID returned by that round's
  create response. A replacement under the same name fails the API delete
  precondition and leaves the measurement unverified.

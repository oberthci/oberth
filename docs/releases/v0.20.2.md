# v0.20.2 release candidate

This candidate builds on v0.20.1. Plain `claude`, with no launcher script and
no environment variables, gets every Oberth MCP benefit Claude Code allows
without a flag (#1519), and the Claude Code documentation now says exactly
what needs a flag (#1520). Everything is generic; no run status, label or
layout is added, and no migration.

**MCP tools: 92 → 92.** No tool is added or removed and the server is
unchanged. The changes are in the CLI, the installer and the docs.

## `oberth client setup` (#1519)

- **One command per machine.** `oberth client setup` registers Oberth as a
  user-scope Claude Code MCP server with `claude mcp add-json oberth --scope
  user`: an HTTP `url`, a `headersHelper` that reads the token when Claude
  Code connects, and `"timeout": 630000`. It trusts the deployment's CA
  through `env.NODE_EXTRA_CA_CERTS` merged into `~/.claude/settings.json`
  (every other key and the key order are kept), or with `--ca-trust system`
  the operating system trust store, which it checks and, when the CA is
  missing, prints the `sudo` command for. `--ca-trust none` is for a publicly
  trusted certificate. It ends by running `claude mcp get oberth` and fails
  unless the server is Connected.
- **Idempotent, and it says what it did.** Each target prints `no change`,
  `registered`, `updated` or `set` with every difference (`timeout: unset
  (Claude Code default 60000 ms) -> 630000 ms`). `--dry-run` prints the same
  plus the `claude` commands and changes nothing. A hand-made entry with an
  HTTP url, a working `headersHelper` and the timeout is kept as it is; one
  with a literal or `${OBERTH_TOKEN}` `Authorization` header, a helper that
  embeds a token, or no timeout is replaced.
- **No secret is written.** The token never leaves the token file or secret
  store: not into `~/.claude.json`, the settings file or the `claude`
  argument list. A literal `OBERTH_TOKEN` in the environment is ignored, with
  a note. A `--token-file` (and the default `~/.config/oberth/token`) is
  refused unless it is mode 0600.
- **Values come from the CLI's configuration.** `--url`, `--ca-file`,
  `--token-file` and `--token-command` fall back to `OBERTH_MCP_URL`,
  `OBERTH_BASE_URL`, `OBERTH_CA_CERT`, `OBERTH_TOKEN_COMMAND`, the `env` and
  `mcp.json` files `oberth install` writes, the files in `~/.config/oberth`
  and, for the URL, the server Claude Code already has registered. A conflicting
  `NODE_EXTRA_CA_CERTS` that names another bundle without the Oberth CA is an
  error, never overwritten. `CLAUDE_CONFIG_DIR` is honoured.
- **`oberth install` uses the same path.** Choosing MCP access on an
  interactive install now registers the same entry (the timeout was missing)
  and trusts the CA in Claude Code's settings, replacing a stale entry instead
  of failing on `add-json`'s "already exists". `~/.config/oberth/mcp.json`
  carries the timeout too.

## Why the timeout

Claude Code's default per-request timeout for an HTTP MCP server is 60 s.
`run_wait`, `wait` and `promote_status` block server-side for up to 600 s, so
a registered entry without `"timeout"` cut every long wait at one minute.
630000 ms covers the longest wait plus its final heartbeat. Live check
(Claude Code 2.1.322, `claude -p`, no `OBERTH_TOKEN` or
`NODE_EXTRA_CA_CERTS` in the environment): the debug log shows
`timeoutMs: 630000`, and `run_wait {timeout_s: 600}` on a running run
completed in 10 m 0 s with `state: timeout`. An interactive session moves an
MCP call longer than 120 s into a background task and delivers its result
when it returns; `-p` waits in the foreground.

## Docs (#1520)

- `docs/agent-events.md`, Claude Code section: plain `claude` (and `-p`, the
  Agent SDK) gets all tools, `run_wait` and `events_since`, and no push. Push
  needs `claude --dangerously-load-development-channels server:oberth` per
  session: interactive only, a confirmation dialog at each start, ignored in
  `-p` and the SDK, and no setting replaces it (Claude Code 2.1.322). The
  `export OBERTH_TOKEN` and `NODE_EXTRA_CA_CERTS=` shell lines are gone.
- `docs/mcp-setup.md` documents `oberth client setup`, adds the timeout to
  every example and fixes the literal-header example's `"type": "url"` to
  `"http"`.
- `docs/mcp-protocol.md` no longer says the endpoint issues no session ID,
  advertises only `tools` and answers resources with `-32601`. Since v0.19.0
  `initialize` returns `Mcp-Session-Id` and declares
  `experimental["claude/channel"]` and `resources.subscribe` when agent events
  are available; the doc says what the session is for and when `-32601`
  still applies.

## Upgrade notes

1. No migration and no server change; the chart renders as before.
2. On each machine that runs Claude Code, run `oberth client setup` once
   (`--dry-run` first to see the change). A machine configured by hand the same
   way reports `no change`. Restart running Claude Code sessions to pick up the
   new entry.
3. A launcher that exported `OBERTH_TOKEN` and `NODE_EXTRA_CA_CERTS` is no
   longer needed for tools; keep `--dangerously-load-development-channels
   server:oberth` on the sessions that should receive pushed events.

## Rollback notes

- A v0.20.1 CLI leaves the registered entry and settings as they are; they
  are Claude Code's own configuration and work without Oberth's CLI.

# v0.20.3 release candidate

This candidate builds on v0.20.2 and fixes the security and reliability
findings of the full code review. Everything is generic; no run status, label
or layout is added, and no migration.

**MCP tools: 92 → 92.** No tool is added or removed. Tool descriptions for
hold servicing and branch prune changed.

## Security

- **Reserved workflow metadata.** A branch workflow can no longer write
  `oberth.ci/` or `workflows.argoproj.io/` labels or annotations through
  `spec.workflowMetadata` (labels, annotations, labelsFrom), including through
  templated keys. Such keys could take over a run's ownership record, which
  wedged cancel, adopt and the admission slot, or hide the run from its Argo
  controller.
- **Reserved release mutex.** A branch workflow can no longer claim the
  `oberth-release` mutex at workflow, `templateDefaults` or template level,
  including through a templated name, so it cannot block every release. Other
  mutexes and the `oberth-sync-limits` semaphores work as before.

## Reliability

- A publication or promotion that fails with Oberth's own git-ssh transport-failure
  message is retried with backoff instead of failing on the first
  attempt.
- A Workflow delete that the Kubernetes API briefly refuses during a cancel or
  supersede no longer restarts the server, whether it happens in the dispatch
  loop or in a run's own worker. The deletion is retried and the run's
  admission slot is released once the delete succeeds.
- A run whose steps passed but whose upstream publication failed says so in
  its reason line, with the retry command (`run_rerun` or `promote_retry`).
- Branch prune judges "merged" against the default branch as the forge last
  confirmed it, not the mirror's copy. It refuses to plan when that head is
  unknown, and says to publish the default branch or wait for the next refresh.
- Admin CLI commands refuse a `--database` path that does not exist or is
  empty, instead of creating a new database.
- The unreachable promotion CI-issue projection is removed; promotions still
  file no CI issues.

## Agents and MCP

- `oberth mcp call` takes its deadline from the tool's own timeout argument
  plus 30 s: `run_wait` waits its full 600 s and `run_hold_exec` up to 900 s.
  Other tools keep 60 s, and `--timeout` still overrides. `run_wait`,
  `events_since` and `run_hold_list` reconnect across server restarts.
- Any uplink whose scope covers a run's repository can service its holds
  (exec, patch, continue, abandon) without the admin token. The servicing
  uplink is recorded in the assist event and the audit log.
- `run_hold_list` and `run_wait` holds carry `abandon_at`. The hold policy
  reports `hold_ttl` and `exec_timeout` as duration text plus `hold_ttl_s` and
  `exec_timeout_s` in seconds, instead of nanosecond integers.
- `retry_hint` tells a step that ran over its ephemeral-storage budget to raise
  the limit instead of fixing the code; a node-pressure eviction is reported as
  infrastructure.

## Breaking default: one spelling per field

HTTP and MCP responses send record fields once, as snake_case. The Go-style
duplicates (`ID`, `RepoID`, `Run`, `Steps`, ...) are gone unless the request
asks for them with the `X-Oberth-Go-Field-Names: 1` header or
`go_field_names=1`, or the CLI runs with `--go-field-names` /
`OBERTH_GO_FIELD_NAMES=1`. A full `run_get` shrinks about four times. This is
an announced exception to the compatibility policy, documented in
`docs/api-compatibility.md`. The bundled CLI and dashboard read both shapes;
reload open dashboard tabs after the upgrade.

## Upgrade notes

1. No migration. Upgrade as usual.
2. Scripts that read Go-style keys from `/api/*`, `oberth runs --json` or
   `oberth mcp call` output must switch to snake_case or set the opt-in.
3. A repository whose own workflow declares the `oberth-release` mutex, or
   sets `oberth.ci/` or `workflows.argoproj.io/` keys through
   `workflowMetadata`, is refused at admission with a message naming the field.

## Rollback notes

- v0.20.2 accepts the same database. Clients that adopted snake_case keep
  working against v0.20.2, which sends both spellings.

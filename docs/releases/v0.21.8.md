# v0.21.8

## R2-1 — Ready installation with pending forge authorization

- `upstream add --no-wait` registers and prints the public deploy key without a forge authentication or repository probe, including existing keys. Host-key pin validation remains mandatory. Pending registration permits readiness and certificate-authenticated MCP access.
- Install JSON includes the upstream name, URL, public key, fingerprint, settings link, pending/verified state, and an exact command for the selected cluster. An `upstream_key_pending` check carries the key inline.
- Install exits 3 when it is Ready with only key authorization remaining, 1 for real failures, and 0 when all checks pass. The plugin presents the public key and settings link directly from JSON, with repository-specific and machine-user guidance for GitHub.
- Failed `--also-upstream` registrations retain exit 1, including when the first upstream is pending or already configured. Client setup and credential delivery still complete before reporting the failure.

## R2-2 — Advertised endpoints and readiness-first verification

- Install saves advertised client host and port choices in Helm-owned Service
  annotations. Verify reuses them without client flags; explicit flags override.
- Changing only an advertised host or port on a same-version install rerun
  reconciles the release so later verification retains the new endpoint.
- `/readyz` and in-pod `oberth admin readiness` expose fixed, secret-free reason
  codes. An unready deployment blocks dependent HTTPS and SSH checks with its
  readiness cause instead of network or certificate remedies.
- Dry runs allow existing certificate and secrets output paths, preserve their
  contents and avoid reading recovery credentials.

## R2-3 through R2-7 — Plugin install and repository polish

- Keep pre-install URL/CA settings optional with empty defaults, explain unset
  notices up front, and document CLAUDE_CONFIG_DIR-aware identity paths.
- Keep install guidance on DNS client names and DNS-only CA constraints while
  IP constraints await the Bun fix.
- Probe planned client endpoints before the install review and propose local
  k3d/Docker published ports; ambiguous, unrelated and remote-daemon bindings
  are refused as proposals. Every cluster keeps the same review gate.
- Bind each repository's SSH command to the selected installation and pinned
  host key, using authenticated server repository paths and exact printed push
  URLs. Global Oberth SSH aliases no longer select a push destination.
- Support home-relative upstream paths and custom SSH forges with manual key
  registration and authoritative host pins.
- Explain that assisted fixes need a committed, unassisted green run before
  promotion, with a helper option for that one unassisted push.

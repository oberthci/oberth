# v0.17.81 admission update

Memory admission now reserves the concurrent sum of container memory requests,
plus executor allowances and max(1Gi, 10% of declared run memory) headroom.
Kubernetes continues to enforce container limits and schedule pods by requests.

Before relying on increased concurrency, review existing memory requests that
were never measured. A low request paired with a high limit now reserves less
capacity. Containers without complete requests or positive memory limits retain
legacy size admission. No workflow resources are rewritten.

Administrators can configure the fixed minimum and proportional component using
`--admission-memory-headroom-bytes` and `--admission-memory-headroom-percent`, or
`admission.declaredResources.memoryHeadroomBytes` and
`admission.declaredResources.memoryHeadroomPercent` in the chart. Unset settings
use defaults; explicit zero disables that component. Both components must be
zero to disable headroom. Existing IO/run ceilings and host protections remain.

This admission update requires no database migration. See
[declared resources](../declared-resources.md) for accounting and upgrade details.

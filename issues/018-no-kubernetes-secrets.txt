ISSUE 018: Keep installation and runtime credentials out of Kubernetes Secrets

Status: Open
Priority: High
Reported: 2026-10-04

Rule
Oberth must not create or depend on Kubernetes Secret objects. Store upstream
SSH identities, server SSH identity and HTTPS private keys in OpenBao. Use
projected short-lived service-account tokens for Kubernetes authentication.
Public trust anchors belong in ConfigMaps. Runtime key files belong on tmpfs.
OpenBao's own TLS bootstrap keys remain on its protected persistent volume,
so starting OpenBao does not depend on access to the store it is starting.
Helm release metadata must use ConfigMaps and must contain no private material.

Acceptance
A fresh supported installation creates zero Secret resources in its namespaces.
Chart rendering creates no Secret resources. Workload RBAC grants no Secret
access. Importing a work key writes it only to OpenBao and runtime tmpfs.
Keys survive Oberth pod replacement through OpenBao and preserve fingerprints.
Migration preserves existing identities and requires explicit administrative
access; it must never silently regenerate a host or upstream identity.

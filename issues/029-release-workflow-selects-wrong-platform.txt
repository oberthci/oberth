Title: Release workflow selects node architecture for amd64-only publisher tools
Status: Fixed in release pipeline; awaiting end-to-end release verification
Observed: 2026-10-05

The v0.17.10 release workflow failed in install-helm before publication:
`go: cannot install cross-compiled binaries when GOBIN is set`. The
multi-platform Golang image selected arm64 on an arm64 kind node while that
step sets GOARCH=amd64. Other release setup assets, including the reviewed
bootstrap tool hashes, cosign binary and Node archive, also target amd64.

Pin the exact Linux amd64 child manifests for Golang and Trivy in release.
Keep branch CI on the corresponding multi-platform Go index, which selects
arm64 on the kind node. An initial CI attempt with the amd64 Go child passed
vet, lint, chart, security and Helm, but its tests exceeded the one-hour
workflow deadline under emulation. The pipeline test now checks the reviewed
Go index/amd64 child pair and exact patch release. Both child manifests ran
as Pods on the arm64 kind node.

A second local branch run returned to native CI and passed setup and vet, but
Trivy's vulnerability DB download ended with an unexpected EOF and the lint
Pod missed its start deadline. The complete internal/argojob package passed
in the pinned native Linux Go image. The branch was published to GitHub for
review with these CI limitations recorded.

Acceptance: branch CI and release admit the pinned images; install-helm and
the complete release workflow pass on the arm64 kind cluster; curl and the
Homebrew tap resolve the published release. Do not move the failed immutable
v0.17.10 tag; use a new version after merging the fix.

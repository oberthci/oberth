ISSUE 008: Review makes an inaccurate blanket claim that no secrets reach disk or etcd

Status: Open
Reported: 2026-10-04
Affected version: Oberth v0.17.9 (6f40126bc8f6), macOS

Priority: Medium
Evidence: UI and cluster resource types observed; no private key values are needed for this finding.

Reproduction
Select production OpenBao, inspect the review promise, then inspect the kinds of credentials persisted in Kubernetes Secrets and OpenBao storage.

Observed behavior and proposed change
Blanket secret-storage guarantee is false as written.
Screenshot 15.52.35: 'no secret leaves memory: none on disk; none in etcd'.
Live cluster contains TLS, SSH host-key and upstream private-key Kubernetes
Secrets, and production OpenBao has persistent storage. This is separate
from the narrower intended claim about release-secret delivery.
Fix: explicitly name which credentials are memory-only and which are
persisted, where, and why. Do not make a universal statement.

Title: Preserve private identities when migrating existing installations to OpenBao
Status: Implemented as preflight verification (v0.17.11); manual seeding documented
Evidence: preflightServerIdentities in internal/installer/identity_preflight.go

The installer verifies that server, upstream-key, and known-hosts identity
bundles are present in OpenBao before upgrading a Secret-backed deployment.
When a legacy Deployment (Secret volumes) is detected, the administrator must
seed the identities into OpenBao manually with BAO_TOKEN, then re-run the
installer with --install-secretstore. The preflight cross-checks the OpenBao
server certificate against the running pod's certificate and prints the SSH
host key fingerprint (public data only) so the administrator can compare it
with their known_hosts entry.

Certificate rotation: when the server certificate lacks goproxy SANs required
by the live argo.goProxy configuration, the preflight rotates the certificate
in place (CAS-bound write of tls.crt only, private key unchanged, same NotAfter)
and updates watchTunnel.originCACert when the live value pinned the old leaf.

The chart's lookup-based gate (deployment.yaml) and the installer's
rejectLegacySecretDeployment function have been removed in favour of the
preflight, which runs on both real and dry-run paths.

ISSUE 010: Copying one credential enables acknowledgement and discard of all credentials

Status: Open
Reported: 2026-10-04
Affected version: Oberth v0.17.9 (6f40126bc8f6), macOS

Priority: Medium
Evidence: Source-confirmed risk; live test saved all three values and did not intentionally lose credentials.

Reproduction
In a disposable setup credential ceremony containing root, unseal and bearer values, copy only one entry and inspect whether Enter is enabled for every value.

Observed behavior and proposed change
Secret ceremony can discard uncopied credentials.
Screenshot 15.52.59. Source-confirmed in ceremony_token.go: one 'c' copies
only the selected credential, sets a global revealed/copied flag, and Enter
acknowledges and wipes ALL credentials. There is no per-item saved state.
Also, copy reveals all values on screen; the parent footer omits the up/down
selection hint that the ceremony itself defines.
Fix: per-item acknowledgement, visible selection help, and separate copy
versus reveal behavior. Give root token, unseal key, and bearer token their
own purpose/storage instructions; the Claude settings path is only relevant
to the bearer token. 'Stored as digests only' should not cover all three.
